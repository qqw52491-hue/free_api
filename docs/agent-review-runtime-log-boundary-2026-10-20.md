# 终审日志进入验收指纹的重复误拦

## 真实事故

会话 `79788637-b98b-4503-8785-e1150d4b25b6`、运行
`bf73a035-d9c9-4f8a-a317-eea61510e8a3` 在 free_api 仓库内排查模型列表未刷新的问题。
2026-10-20 13:28～13:32（北京时间）数据库记录了 5 次
`finish_review:passed`，随后均为 `finalization:prepared_blocked`。
拦截原因一致：验证/终审期间交付内容发生变化。

这不是 Git 忽略规则失效，也不是模型连续否决报告。

1. 两条 SQLite SELECT 命令进入保守副作用台账。
2. Git 无变更时，`collect_review_material` 转到近期文件补充扫描。
3. 补充扫描未排除 `agent_logs`，把本次分流和终审日志收进材料。
4. 宿主归档新的审查响应，改变日志内容。
5. 审查前后材料指纹不同，已通过的审查被作废；重交再次写日志，重复触发。

已保存的审查请求中能看到 `src-tauri/agent_logs/...__triage.json`
及 `...__finish-review.json` 的文件内容段落。台账、请求材料、日志写入及哈希比较
共同解释了这条触发链；无需归因于评分或模型拒绝。

## 修复边界

把已知运行日志目录识别提取为共享规则：精确目录名 `agent_logs`，适用于根目录和嵌套目录。
影响面写方线索和验收材料使用同一规则。

- 磁盘扫描在递归进入日志目录前剪枝，日志不消耗文件扫描额度。
- 审查材料、变更路径和内容哈希共同排除这些日志，避免只隐藏预览却残留指纹。
- 兼容路径分隔符；`config/agent_logs.json`、`my_agent_logs/report.json` 等相似名称仍保留。
- 源码、普通 JSON 配置、Markdown 报告及原有完整内容指纹保留。

不将所有 `.gitignore` 项自动排除，不推断任意 SQL 是否只读，不删除日志，
不修改 Git 基线、不伪造审查结论。显式读取历史日志的取证工具仍可使用。
这条自动扫描约定将 `agent_logs` 目录作为运行记录；若业务文件放入同名目录，
也会退出自动材料收集，因此它不是通用的文件语义识别算法。

长期可以评估把宿主日志移到工作区外的应用数据目录；这涉及日志查找和现有工具，
不属于本次局部修复。工作区外存储也不能替代明确的自动材料边界。

## 用户授权后的通用变化处理

用户随后明确要求“每次变化让审查决定，不要写成强制”，因此本轮进一步退出
“只因材料哈希变化就打回”的规则，不继续扩充目录黑名单。

1. 材料稳定时沿用一次正常终审，不新增模型调用。
2. 终审已批准但观察到材料变化时，补充一次现有终审，附路径、前后指纹和
   前后材料节选；补充材料不会触发旧否决缓存。
3. 审查员按现有 `blocking_issues` 和结论判断变化是否影响交付，
   可认可无关运行产物；不新增 `change_verdicts`、逐项填表或强制补验。
4. 已有具体 blocking、真实宿主复验失败或审查通道失败保留原处理，
   不借材料变化重开空白审查并丢弃失败事实。停止信号仍阻止交付。
5. 如果补充复核期间仍在变化，不无限追加审查，也不自动合成缺陷；
   在预检、最终实时正文和持久化聊天中披露后续变化尚未取得独立结论。
   收据保留已审范围，未审的最新版本不会被标成可复用收据。
6. 正式提交前原来还有一次哈希硬拦，也改为窄窗变化披露；
   scope、契约和交付正文状态的一致性检查仍保留。

新观察字段 `material_notices` 是宿主内部的可选披露数据，旧收据缺失时默认为空；
没有新增模型必填字段、配置开关或数据库迁移。已有 `mechanical_only` 分流不自动升级。
真实文件的完整内容指纹仍用于发现变化和避免复用旧版本，并不自动等同于质量不合格。

这是有意放弃文件全程静止的保证，交付依据是已有证据与审查判断；
持续变化中的最新文件可能尚未被审查。补充审查仍沿用现有的取证与超时预算，
条件触发时会增加审查成本，本地测试不证明真实模型一定更快或判断正确。

## 验证方式

覆盖 Git 干净但有保守台账的补充扫描、非 Git 补充扫描、已跟踪/未跟踪日志、
根/嵌套目录、扫描额度，以及真实源码/配置/报告变化。

本地假模型经过 `evaluate_completion` 的真实终审入口，在响应时写入合成日志：
日志变化应允许交付并复用就绪收据；真实配置变化会进入补充审查，
审查员认可可交付，有实际 blocking finding 仍拦截。

## 生效与限制

需要重新编译并重启后端才会生效；已经运行的旧进程不会被源码修改热更新。
本次不修改真实数据库、旧收据或任务状态。旧的被拦收据不能直接变成通过，
续跑须针对修正后的材料重新评估。

本地回归不能证明真实模型的诊断必然正确，也不能证明其他自动扫描路径都没有噪声。
