# 第一版：成员直接通信与结束后的只读收信接续

## 行为

同任务树的 `child_task.send` / `send_message` 可以发送给运行中或成功结束的通用任务、worker、writer。消息先登记，运行中的接收者在安全边界接收；接收者成功结束后仍有未接收消息，宿主创建新的 `readonly_inbox` 执行。原执行及其正式交付不重新打开。失败、取消、未知目标不自动恢复，reviewer 的正式入口保持原样。

显式 `ask` / `ask_agent` 沿用原有只读答复契约；答案保存给原请求者。请求者已经成功结束时，同样由关联只读执行接收。新的收信执行读取原交接及信箱，根据内容决定是否通过 `send_message` 回复发送者；其 `finish` 只保存处理结果，不自动制造下一封答复。命令、写入、实施、再派发仍不可用。需要实施时沿用负责人显式续派。

主 Agent 不承担问答中转；可以查询同树协作进度，并通过已有子执行回执回收处理结果。成功交付前检查已经受理的在途工作；失败和取消仍可结束并保留未完成事实。只读接续会调用原接收者的模型，使用既有预算及并发额度。

## 事实与原子边界

- 复用 `agent_messages` 和 `agent_child_runs`；消息表新增可空 `claimed_run_id`，旧消息不迁移语义、不自动重放。
- 原 `target_run_id` / `target_session_id` 保留接收归属，`claimed_run_id` 指向本次收信执行。认领和关联执行登记同事务提交，重复触发不会建立两个接收同一消息的执行。
- 普通 Agent 发送标注为 `agent_material`，显式追问的答案为 `peer_answer`。宿主通知保留原类别，不自动唤醒通知接收者。来源类别不能由消息正文指定。
- 发送登记、认领、主任务成功终态共用 SQLite 写事务排序；待认领消息已经计入在途，额度不足时仍可查询为 `pending_start`。
- 实际启动及模型调用在事务外。消息登记、普通子执行结束、通用任务结算、只读答复结束、僵尸执行回收后及交付对账时，调用共同协调入口；没有新增周期扫描器或贯穿模型调用的大锁。
- 接续复用原执行器。读取信箱时，消息身份、上下文历史与 `delivered_at` 同事务保存；`in_context` 只说明已接收，不说明模型理解或目标完成。
- 一轮成功收尾时，将尚未接收的新消息解除当前认领，交下一轮关联执行。旧执行只写自己的 ID，不覆盖新执行。
- 启动失败保留失败执行和未接收记录，不反复自动重试；父任务通过现有回执获知错误。应用恢复沿用原中断处理，不自动重放模型或外部操作。

## 查询

`child_task.list(offset?)` / `team_status(offset?)` 返回原成员列表，并附 `collaboration` 分页视图：消息 ID、发送者、原接收者、关联执行、登记和接收时间、执行状态与接收状态。每页最多 100 条，返回 `has_more` 和 `next_offset`。原成员列表补充 `result_available` / `collected_at`，区分结果产生与负责人回收。`receipt(message_id)` 可回查原文、原目标及关联执行状态。

这是模型与界面可以共用的查询数据；本版没有新增桌面协作面板。查询不核销消息，也不生成完成百分比。

## 验证与边界

新增 9 项本地回归，覆盖双方发信后结束、线程并发认领、接收事务失败回滚、失败记录与查询、主任务结束后拒绝新信、旧执行收尾与晚到消息、真实启动失败、额度不足暂存，以及普通消息登记与正式成功提交的线程竞争。既有回归同时调整为必须由真正接收方接收答案，主任务回收不能代替它。

信箱相关 22 项通过；两项原有本机 SSE 假模型用例因沙盒禁止 HTTP bind 无法执行。隔离数据目录的完整 Rust 回归 1391 项通过、116 项失败、10 项原有忽略，跳过真实剪贴板；逐项核对 116 项均在本机监听时收到 PermissionDenied / Operation not permitted。最初未隔离数据目录的一轮还遇到应用目录只读，隔离后这些失败均消失。

Rust `check --tests` 和构建通过。未调用付费模型、未重启桌面应用或改写真实会话；未验证真实模型如何选择回复，以及 UI 端到端表现。
