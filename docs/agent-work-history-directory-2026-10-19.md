# 工作历史目录：L0 → L1 第一轮落地

## 范围与含义

本轮把工作过程组织为可搜索、可分页展开的目录，不生成语义过程摘要、L2 结果卡或 Lesson，不改压缩主线。目录标签描述工作对象，不证明完成。失败、参数拒绝与后台派发回执仍是观察/尝试；是否真正执行、业务是否通过，要看各自原文与验证。

已有字段的口径统一为：`plan_id` 标识工作组，`plan_title` 是可改名的标签；显式 ID 优先，省略 ID 且 `new_plan=true` 才自动分配新组。回到旧问题可复用旧 ID，小任务可只有一组。分组是建议，不新增步数阈值、语义质量检测或交付门禁。

## 实测依据与限制

只读抽查本机最近 8 条非评测运行。其中 `01608301` 的 50 条步骤全部保存为 `plan-1`，标题有多次变化，包含“定位审计日志拦截与写入实现”和“审计日志报文隐藏字段设计与落地”。这是已保存的编号/标签形状，不能单凭它判定真实业务应分几组，也不能证明本次建议必然改善模型判断。

本轮测试用脱敏合成事件回放这个结构：仍保留一组 50 条观察，不通过标题相似度自动拆历史。未来是否更好找，需要新任务中的真实模型轨迹对照；本轮没有付费模型实验，没有对旧库补写、重组或重建归属。

## 身份与恢复

- 宿主生成 `history_task_id` 并保存在 durable checkpoint；同任务恢复沿用，新任务继承旧历史时不继承该 ID。
- `PlanState` 的活动组、编号及各组标题一起保存。改名不换组，返回旧 ID 不借用另一组标题；自动编号避开已见过的显式 `plan-N`。
- L1 的身份由会话、任务和计划共同确定；L0 保留独立的 `output_id`，`parent_id` 指向 L1。
- 老检查点缺少分组信息时保留未知，不根据时间、步骤号或标题推测归属。首次恢复产生的新宿主身份随后持久化，不为旧事件补造关系。

## 派发与晚到结果

派发前保存已解析的计划身份和任务状态，并冻结派发作用域。异步任务在真实任务记录创建时，把确切 job/child ID 与该快照关联，保存在既有 L1 元数据中。同步本地工具的 blocking 线程显式携带作用域，不使用可被其他请求覆盖的全局“当前计划”。

后台完成回执沿 ID 找派发时的目录；子任务续跑继承前驱来源。缺失或歧义时不借用回收时的活动组。晚到结果不回滚后来更改的目录标签。后台回执用会话和异步 ID 派生精确输出身份，原文落库的主键去重覆盖并发/跨通道重放；不伪造一次新的主 Agent 步骤号。

## 检索与展开

搜索原始历史与记忆候选后，按 `output_id` 合并同一观察，保留目录归属。两条分支交错合并后再截断，披露已知 `has_more`，避免普通历史先占满返回名额。仅有目录标签命中时不会宣称对应工作已经完成。

`task_store.get_work_group` 接收检索返回的 `group_id`（episode ID 或 L0 的 `parent_id`），可选 `offset`、`limit`；默认 10 条、最多 25 条，每条返回有界预览、状态和原文引用。沿用会话归属校验；详情用既有 `get_step_output` / `search_step_output`。目录本身不自动展开整段日志。

## 成本与失败方式

没有额外模型调用或新的模型必填字段。增加一段静态分组建议、一条内置工具目录说明，以及宿主身份/索引维护；同标签的目录不反复重写 FTS。目录写入失败只记录诊断，原始输出仍保存、工具照常返回，目录不是新的业务成功条件。

## 本地验证

新增用例覆盖：编号与改名/回访、同任务恢复及新任务隔离、旧格式兼容、目录分页及归属、精确原文回查、同一观察去重、真实检索入口、后台晚到、blocking 作用域、子任务注册与续跑、改名后晚到、并发回执重放、索引失败降级、50 步单组形状回放，以及当前目标与缓存锚点的命名分离。

最终验证：完整 Rust 回归 1190 通过、10 项既有忽略、跳过 1 项真实剪贴板测试；`cargo check` 与前端类型检查通过。完整回归使用独立临时数据目录及本机模拟服务。
