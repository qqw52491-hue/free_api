# 视频任务的响应恢复与命令诊断

## 事故证据

会话 373dd4ab-7219-4f37-8b57-072e13cb0441，运行
85d10b5c-3902-407f-b377-495be0834415（豆子王国视频）。

运行最终成功，约 14 分 12 秒。49 次主模型调用中有 8 次解析失败，
合计约 282 秒，每次 completion_tokens 均为 8192。
旧归档没有 finish_reason，不能仅凭 token 数认定每次均由输出截断造成。
旧代码在正式回复为空时把 thinking_text 用作指令候选，导致思考内容被当成协议错误反馈，
其中的 JSON 示例也可能被当作可执行指令。

编码失败时，stdout 有 Chrome not found，stderr 有 MP4 文件不存在；
失败反馈优先选 stderr，遗漏前面的原因。后台渲染运行约 200 秒，
但显式后台派发的完成路径把 duration_ms 固定写为 0。

## 局部修复

- SSE 保留供应商 finish_reason，随主调用和辅助审查归档；缺失保持未知。
- 主执行器只解析正式回复。正式回复为空或供应商明确报告 length/max_tokens，
  归为 output_incomplete，不修补并执行被截断的响应。
- 内外重试使用相同的错误反馈：说明本次未执行，建议提交下一项较小的完整操作。
  不改变模型输出预算、重试次数或审查规则。
- 不再把整个响应拼进错误字符串和用户日志；原始正文与思考分开归档。
- Shell 失败反馈保留 stdout、stderr 各自有界尾部并标明节选，
  完整工具输出仍按原路径保存。没有按错误关键词猜测业务成功与否。
- 显式后台进程从启动到 wait 完成计时，写入既有任务 duration_ms。
- 视频技能示例补 Chrome 路径、短临时目录、相同帧率和失败退出码说明；
  图像查看能力按实际使用披露，不再声称模型必然没有图像输入。

有界错误、SSE 结束原因、真实 Shell 双流失败与 Unicode 尾部。
既有后台 sleep 1 集成测试补充 duration_ms >= 900 断言。
测试不调用付费模型，不修改真实会话或视频。
