# 配置优先级与嵌套合并复核

起点为 `197bef4`，`main`，工作区干净。此次直接读取本地源码并运行回归，不依赖对话里的修改报告。目标是检查当前规则，修复可复现冲突，不将建议表直接替换为新优先级。

## 五项规则

| 项目 | 实际规则与检查结果 |
|---|---|
| 执行方式 | 固定入口 / 明确派发 profile 优先，其后角色默认、唯一允许类型推断，最后 task。新增 18 组选择组合验证；角色允许类型仍在正式派发处检查，不允许的类型拒绝派发 |
| 工作流程 | 普通字段按派发明确值、角色自定义、公共默认、原入口缺省合并。人工批准属于例外约束，不能按普通偏好任意降级 |
| 工具权限 | 角色与派发限制先求交，正式登记再与父执行有效权限求交，调用时再授权。嵌套只传播工具上限，不将父任务工作流程作为子任务的公共默认 |
| 模型 | 角色卡绑定优先于对应人工工位；没有绑定时使用派发指定模型，再继承父执行实际模型。与绑定冲突报错，恢复已有执行读登记模型。本轮不改变模型顺序 |
| Checkpoint | 已登记执行保存有效配置；公共默认只用于新派发。任务续跑沿用原模式、阶段及审查策略快照，不因后来调整公共默认而改写 |

继承语义按层处理：某层未指定或合法可空字段为 null 时，保留上一层值；明确 false 关闭该层覆盖的自动环节，不能当成未配置；明确 true 开启。关闭不撤销已有有效阻塞和明确验证要求。模型 ID 必须是有效的非空精确值，显式 null 仍是参数错误，不将三态规则机械套到所有字段。

## 已复现并修复

1. **空值清掉角色覆盖。** 角色 `cross_review + delivery`，阶段值 `stage_review=true, final_review=false`，派发相应字段均传 null；原实现将角色字段清空，公共 `auto + handoff` 等值重新填入。回归修前失败。现在仅对已知合法可空字段跳过 null，未知字段和错误类型仍由原解析器拒绝。workspace=null 也保留角色隔离方式，显式 shared 仍可切换。
2. **通信整组与别名交集误拒。** `child_task` 与 `send_message` 均能授权发送，但原交集产生空表。对照真实 `authorize_call` 的回归修前失败。现在仅补齐原生通信的 send/ask/wait 已知别名，不将任意 MCP 名称中的点号视为动作分隔符。
3. **角色人工批准被显式覆盖或普通入口转换取消。** 角色要求 plan_approval，但派发 auto 可被接受；固定 worker 入口切换还会重置流程。回归修前失败。现在普通 task/worker/writer 保留角色的人工批准要求，冲突报错且不派发；用户仍可明确修改角色配置。正式只读审查沿用专用适配器，不增加内部人工审批循环。

## 保留边界

- 外部 MCP 以实际完整工具 ID 配置权限。`plugin/tool.action` 可能与真实带点工具名歧义，通用整工具/子动作混合限制未在所有外部服务下统一；可能保守误拒。本轮没有用字符串前缀放行来掩盖此问题。需要外部服务内部操作级限制时，还应使用服务端自身授权，不能宣称此处支持任意服务动作粒度。
- 已有未完成子任务在进程退出后、角色又被修改/停用时重建整树，未做完整桌面实测。本轮未重写恢复机制，不宣称所有恢复路径都已证明稳定。
- 没有付费模型、真实 MCP 账户或真实桌面重启测试。没有新增配置页面、模型调用、数据库迁移或语义质量门禁。
