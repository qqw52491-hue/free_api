# 多 Agent 审查与意见流转排查记录

日期：2026-10-22。本文记录本轮已确认的问题、修复和验证范围；本轮发现的具体代码缺口均已修改，不继续扩展排查。

## 流程与身份

审查派发时固定批次（batch）、逻辑任务（task）和尝试序号（attempt）；续跑生成新的执行 ID，但沿用逻辑任务身份。回执经统一归并形成当前有效裁决，再同步自动待办、阶段阻塞和终审移交材料。

历史回执和当前意见分开：失败尝试不自动撤销旧有效判断；遗漏某条发现不等于撤回；不同成员的 F1 不属于同一个问题。撤回和降级按具体来源更新，迟到、重复回执不能借当前活动状态改写归属。人工接受风险保留原始审查意见，只核销能确认来源的对应自动待办。

已有的有效阻塞、明确修订要求和用户停止仍沿用原规则。本轮没有新增模型必填字段、数据库表、审查预算或语义质量门禁。

## 已修复的问题

| 问题 | 原有行为 | 本轮修改 |
|---|---|---|
| 已批准方案再次续审 | 方案仍为 Approved，可能在新审查尚未返回时继续 | 正式同批方案续审回到 Reviewing；失败保留此前有效裁决。阶段对质和补充审查不因此增加方案审批义务 |
| 对质轮次借给其他发现 | 新 F2 可能借用 F1 的轮次；遗漏旧发现也被算作维持 | 轮次归具体发现；仅明确重复阻塞或 maintain 才累计。首次出现、遗漏、失败不计，撤回或降级重置对应状态 |
| 派发失败残留运行状态 | 模型配置不存在时已登记 running；writer 续跑预检也晚于登记 | 配置及既有写入预检前移，启动拒绝不产生幽灵运行行或 writer 工作副本 |
| 定稿提示与实际裁决不一致 | 原始回执含修订文本便可能提示已定稿，即使被打回或病根核对不足 | 提示读取归并后真正生效的批准裁决及定稿权限 |
| 终审移交材料成为历史累加 | 已撤回问题仍残留；不同成员同 F1、同文字可能合并 | 从当前具体发现重算移交清单，带批次和任务来源；只替换宿主能精确识别的旧投影。阶段清账仍保留跨阶段移交 |
| 人工放行后自动待办仍阻塞 | 裁决已人工放行，但原自动 TODO 仍待处理 | 三处既有人工放行入口统一核销本批、来源绑定且描述未被修改的自动 TODO。保留原始裁决、用户编辑、其他批次及来源歧义项；后续新有效意见仍能重新产生待办 |
| 多人回执互相覆盖共同方案 | 手动多人派发或旧回执的定稿标记可能赋予单成员覆盖权限，结果依到达顺序变化 | 派发端关闭多人单成员定稿；消费端依据宿主批次人数再次限制旧标记。单人既有定稿规则保留 |

主要实现位置：

- `src-tauri/src/agent/checkpoint/{plan_ops,review_state,stage_state}.rs`：意见归并、人工核销和阶段移交。
- `src-tauri/src/agent/child_receipt.rs`：实际生效裁决对应的通知。
- `src-tauri/src/agent/child_reviewer/{mod,resume}.rs`、`child_writer/mod.rs`、`child_worker.rs`：派发和续跑生命周期。
- `src-tauri/src/agent/loop_runner/dispatch_{ask_human,child_reviewer,resume_child}.rs`：既有入口衔接。

## 跨平台排查及纠正

最初把 macOS 默认临时目录下的权限测试失败归为运行时权限缺陷；继续核对后发现，正式授权入口已经保存 canonical 物理路径，失败夹具却直接注入原始路径别名，部分断言还混用了别名与持久物理键。不能通过重新解析旧授权到新的链接目标来消除测试失败。

本轮修正五处测试夹具及两处 Shell 测试命令，生产权限规则不变。新增真实授权入口回归，覆盖原生路径拼写、含空格及中文的文件、恢复、离线撤权，以及符号链接改指向后重新绑定。路径规范化继续交给系统，不自行修改 Windows 前缀或统一大小写。

`.github/workflows/rust.yml` 新增 macOS、Windows 原生目录权限任务，分别运行受控访问、项目授权、会话恢复、scout 和附件路径测试；保留已有 Linux 完整构建与测试。新增任务尚无远端通过结论。

## 回归证据

本轮分三批新增 18 项回归（9 项意见与生命周期、2 项路径入口、7 项后续意见流转）。使用临时数据库和本机 HTTP 假模型，未调用付费供应商。

- 同批正式方案续审：在途等待、新修订、失败保留旧批准；阶段和补充审查不误开方案门。
- 三种子任务的真实派发入口：配置缺失不登记 running、不复制 writer 工作区。
- 按发现对质：新问题不借轮次、遗漏不计维持、显式 maintain 可计数、撤回重置。
- 终审移交：同 F1/同文字的独立成员、撤回、自动降级、检查点序列化恢复、阶段清账及旧格式披露。
- 六条阶段回执的全部 **720 种到达顺序**：中途序列化恢复、末尾重复回放后，当前阻塞和移交意见一致。
- 人工核销：保留原始阻塞、用户编辑及其他批次；后续真实续接的新有效意见可重新打开自动待办。
- 多人共同方案：A/B 两种到达顺序均不能借旧定稿标记覆盖共同方案。

最终本机验证：


完整回归使用 macOS 默认临时目录。没有启动桌面 UI，也没有进行 Windows/Linux 原生实机验证；新 CI 配置不等于已证明跨平台通过。

## 保留的边界

旧记录若缺少逐项来源，保留并标为历史参考，不猜测归属或按 F 编号批量删除。此处理避免伪造撤回事实，不表示历史文字仍是当前有效阻塞。

模型是否始终沿用编号含义、是否正确理解材料和给出实质正确意见，仍属于认知判断。此次测试证明已覆盖的宿主状态转换、归属及回放行为，不证明所有多 Agent 路径绝无问题，也不保证真实供应商速度、费用或审查质量。
