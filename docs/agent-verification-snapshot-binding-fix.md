# 验证快照执行绑定修复

## 已复现的缺陷

旧执行器把 `verify_script` 正文当作路径取文件名，再对 `verify_command` 做字符串替换。普通 `sh verify.sh` 未被替换，可能实际运行工作区文件，却被当作快照验证结果。隔离抽取原执行函数复现：快照退出 9、磁盘退出 0 时返回通过；反向组合返回磁盘退出 7。

## 修复边界

- 普通 `verify_command` 保持原样，通过 `sh -c` 执行；不新增命令白名单，不解释业务是否成功，不静默添加 `set -e`。
- 仅当提供非空 `verify_script` 时，用私有 UUID 临时目录保存正文；校验可选 SHA-256，通过子进程环境变量 `FREE_API_VERIFY_SCRIPT` 传入路径。解释器、参数、Shell 组合由调用方选择，例如 `python3 "$FREE_API_VERIFY_SCRIPT" --mode strict`。
- 附了快照却没有声明该变量引用，或引用变量但未附快照，返回原有 `fail-closed`/`passed=false` 形状，明确未执行及修订方式。不猜旧命令文件名，不跑另一份脚本兜底；不修改历史检查点。
- 变量检测仅核对引用声明，不证明 Shell 控制流实际消费该变量（注释、字符串、条件分支均不能由此证明执行）。输出明确是“宿主快照提供记录”，包含路径和 SHA-256，不写成“脚本已被执行/业务已通过”。进程退出码仍是原始 Shell 退出码，验证充分性由模型及审查判断。
- 普通命令可通过 `review_contract_update` 撤下快照：显式将 `verify_script` 设为空字符串，合并时同时清除脚本和旧摘要；null/缺失仍沿用旧的局部更新语义。修订命令且不附脚本也沿用现有方法切换行为。
- 临时目录不使用义务 id；Unix 下权限 0700。RAII 清理覆盖成功、非零、启动失败、超时及 future 释放。不提供后台子进程持有快照的生命周期保证；验证应在前台完成。
- 完成收据验收指纹升级，冻结执行回执增加可默认读取的执行器版本。旧版错误执行器产生的成功不能直接复用；同版本的既有复用条件不变，不修改既有审查或持久化流程。

## 回归与限制

回归覆盖相反磁盘/快照结果、未绑定旧配置、仅脚本无命令、普通复合命令、Shell/Python 解释器与参数、Unicode/引号工作目录、同 id 并发隔离、哈希错误、未附快照、超时/启动失败清理、分支不执行时不夸大回执、显式撤下快照、旧版执行回执不能复用。

本修复不证明此前真实失败运行经过此路径，也不保证模型必然选择正确验证方法。无付费模型调用、不启动或重启桌面应用、不重写真实历史记录。验证结果如下。
