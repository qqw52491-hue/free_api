# 通用任务委派、定向通信与进度（2026-10-30）

`child_task` 接收完整子目标，复用主 Agent 的执行器、上下文、检查点、验证、审查和交付流程。专用 worker、writer、reviewer 及其角色卡、输入约束、输出契约均保留；没有新增通用角色配置页面。

## 当前可用的流程

```json
{"tool":"child_task","params":{"task":"把 A 项目的登录模块迁移到 B 项目，保留 B 项目权限行为，完成适用验证并报告未完成项","context":"必要背景、已知结论或已有 output_id 引用"}}
```

派发立即返回 `child_run_id`。父模型可以查进度、补资料、回答子任务的信息请求；共享工作区修改仍按顺序执行。

```json
{"tool":"child_task","action":"status","params":{"child_run_id":"已有任务 ID"}}
{"tool":"child_task","action":"send","params":{"target":"已有任务 ID","message":"补充接口资料","data":{"api_version":2},"refs":["已有文件路径或 output_id"]}}
{"tool":"child_task","action":"wait","params":{"child_run_id":"已有任务 ID","timeout_secs":180}}
{"tool":"child_task","action":"result","params":{"child_run_id":"已有任务 ID"}}
{"tool":"child_task","action":"resume","params":{"child_run_id":"已结束的任务 ID","message":"请解释兼容性检查中没有覆盖的情况"}}
```

`task` 必填，`context` 可选，合计最多 65536 字符。消息至少有 `message`、`data` 或 `refs` 中的一种，序列化内容最多 65536 字符。数据支持普通 JSON 对象、数组等，长证据优先传引用。身份、工作区、目录权限、模型和执行模式由宿主绑定，任务文字不能授予权限。

## 通信范围和交付含义

- 主 Agent、通用子任务及同一根任务内的 worker/writer 可以定向互传消息；接收方用 ID 指定，`parent` 表示直接父任务，`list()` 查看同树任务（最多 100 项，活跃任务优先）。其他根任务，即使属于同一会话或项目，也不能互相读写信箱。
- 通用子任务需要父任务资料时，可 `send(target="parent")` 提问，随后 `wait()` 等回信。消息可唤醒父任务的消息等待或既有 `wait_jobs`，不会中断正在执行的模型请求或工具；在后续安全边界注入。
- worker/writer 增加可选动作 `send_message`、`wait_message`、`read_message`、`team_status`，动作参数放在既有 `params` 中。文件范围、命令限制、writer 副本隔离、测试与结果契约不变。等待服从各自原有总时长预算。
- reviewer 的一次性审查仍使用原有 `resume_child` 追问/对质，不增加运行中任意消息入口。
- `receipt(message_id)` 查询自己发送或接收的信件。`queued` 表示入队；`in_context` 表示带来源的材料或有界节选及原文入口已和接收方上下文一起保存，**不证明模型已经理解、执行或完成**。接收方结束时仍未投递，会显示 `not_delivered_target_ended`。
- 每封消息单独保留发送方、时间、消息 ID 和原文入口，避免整批反馈截断时丢掉中间消息。较大 JSON 在默认上下文中显示节选，原文按 ID 读取，数据库不截掉原始内容。
- 发送者身份由调用方运行记录提供，忽略载荷里冒充 `sender` 或 `user` 的字段。协作消息作为带来源的材料处理，不进入 `HumanControl::Answer`，不批准方案、不核销人类授权，也不扩展 hard scope。
- 结束后的追问用 `resume` 建立新尝试，绑定 `resumed_from`，携带前次目标/交接的有界历史材料、结束前未投递消息的首批引用。保留原始发送方；更多原信箱材料可 `inbox(child_run_id, offset, limit)` 分页查看，原文可按 ID 回查。不会把旧方案批准或旧验收收据复制为新任务批准。
- 不自动重启已结束的 Agent，不建立任意层级通用委派或无条件横向唤醒网络。通用任务仍只允许一层；已有专用能力可以照常调用。

## 进度与用户操作

桌面主会话增加通用子任务进度卡，可查看当前状态、步骤、最近活动和排队消息；可给指定子任务补充资料、回答其真实人工请求、只停止该子任务。页面重新加载后按已有任务记录重新查询。没有预测完成百分比。

子任务的人工表单使用已有表单组件，但回答直接绑定该子任务的控制通道；普通补充消息不能代替表单批准。子任务等待人工时，`child_task.wait` 保持挂起、不在普通等待窗口到期时消耗模型轮次；收到协作消息或停止仍可唤醒。人工等待结束后继续普通等待逻辑。该状态来自宿主实际发出的人工请求，不是模型自报“卡住”。

子进度封装在 `child_task_progress` 中，不把子任务的 `complete`、人工请求或权威成功状态当作父任务状态，也不发送整项用户任务完成通知。

## 执行、工作区和恢复

- 执行入口仍是 `run_agent_main_loop_in_workspace_inner`。独立运行适配层持有自己的身份和资源，未复制第二份主循环，未递归进入桌面/HTTP 顶层任务入口。
- 每个通用子任务有独立 session、run、任务起点、上下文、检查点和正式收据。父子身份与状态沿用 `agent_child_runs`，kind 为 `task`。
- 一次只运行一个共享工作区的通用子任务。父级原有后台/专用任务先回收；子任务执行时，父模型可以协调消息和使用原有只读入口，按既有副作用分类暂缓父级变更入口。项目锁由父 run 保持；非项目入口补持物理目录锁。同会话重启不会在子执行器尚未退出时通过原有接管路径抢走该锁。Shell/MCP 的原有执行边界不变，不宣称新增 OS 沙箱。
- 父任务停止时先请求子执行器取消，等待真实执行器退出、收停其运行资源，再释放工作区。启动控制通道尚未登记时的取消也会保留。执行器 panic 归为错误，不当作已完成目标。
- 目录权限运行期引用父会话当前投影，撤权同步生效；新可写目录在发布前同时保存子任务起点。父 tmp 中已有证据增加子任务只读入口，宿主提供其绝对路径；项目资源沿用父项目。
- 子任务临时产物在父 tmp 的 `delegated/task-<ID>/` 独立目录，父任务可沿用既有权限读取、集成和登记。交接包含 `artifact_base`，不往源码根复制附件或中间产物。
- 派发键绑定父逻辑任务、步骤和内容；消息重试键绑定发送方运行及该次工具动作。相同重试认养已有记录，不重复派发或入队；显式复用同一消息键却换内容/接收方会报绑定冲突。
- 主执行器的消息注入与 `delivered_at` 通过现有乐观锁检查点写入同一事务；冲突时不发布候选上下文、不核销消息。worker/writer 将带来源消息投影及其既有脱水历史与投递回执一并提交。
- 通用任务的终态经现有自动轮询和 `wait_jobs` 回收，复用统一 reducer。实际副作用带来源导入父任务并去重，和 `applied_at` 共用检查点事务。导入失败时保留回执待重试，不静默核销。
- `execution_ended`、`execution_status`、`delivery_accepted` 分别表达执行结束、执行状态和子目标验收。只有同一 run 的正式成功终态与同一已提交检查点的就绪收据匹配才视为子目标交付；`Ok(())` 或模型自述不足以成功。父任务继续负责集成和最终用户交付。
- `agent_messages` 按根会话归属登记到现有删除/孤儿清理注册表；内部子会话不混入普通会话列表。删除父会话清理记录与会话产物，不把共享源码工作区作为子会话目录删除。
- 应用重启时不自动重放外部操作。状态查询可根据原运行的已提交终态收敛遗留子状态；没有活跃执行器且缺少可信终态时明确显示未连接/待核对，未投递信件继续保留。

## 验证与边界

17 项定向测试覆盖原有通用交接，以及 JSON/引用传递、同树互发与跨任务拒绝、伪造来源、消息键重试、检查点冲突原子性、恢复去重、既有 job 等待被消息唤醒、取消、结束时未投递材料、后续任务读取来源、长消息逐封保留、级联清理、提前取消与等待真实退出、执行器 panic、人工等待不消耗模型轮次。本机 SSE 假模型经过真实 worker 执行循环完成收信、结构化回信和原契约交付。

使用临时数据库、本机端口和物理临时路径测试；不调用付费模型。上述本地回归未调用付费模型、未主动重启实际应用或改写真实会话记录；随后用户发起的实际委派运行见下文。桌面手动补充、人工表单和停止操作尚未逐项实测。既有默认 macOS 临时路径下的 7 项失败在前轮未修改的 HEAD 副本中已复现，保留原实现；本轮沿用物理临时路径验证。


本轮完整 Rust 回归 **1490 通过、10 项原有忽略、跳过 1 项真实剪贴板测试**（物理临时路径）；17 项通信/通用任务定向测试通过；前端类型检查、前端生产构建及 Rust 构建通过。构建保留原有 reviewer_persona 未使用赋值及前端分包提示，不扩大范围修改这些既有事项。
