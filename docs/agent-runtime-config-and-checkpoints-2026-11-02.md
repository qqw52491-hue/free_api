# 子任务动态执行配置、独立检查点与角色页面（2026-11-02）

后续普通 worker/writer 已改为通用执行角色预设，默认共享工作区与能力；以下保留初次实现记录。当前入口和兼容边界见 [普通子任务统一执行](agent-unified-presets-2026-11-02.md)。

## 这版接通的链路

角色页面保存默认组合 → 派发入口解析角色与显式参数 → 登记实际配置、原始输入及初始检查点 → 执行时校验工具范围 → 保存进度与接收记录 → 按交接或完整交付模式提交结果。

公共入口是 `child_task.dispatch`，`profile` 可选 `task / worker / writer / reviewer`。兼容的专用派发入口保留，共用角色配置解析。完整阶段、动作执行和审查仍各有适配代码，复用公共执行驱动与配置／持久基础；隔离副本、审查裁决和既有结果契约保持各自语义。

| profile | 执行与结果 |
|---|---|
| task | 原有完整主循环，可配置方案流程及 handoff/delivery；独立 AgentCheckpoint |
| worker | 共享动作执行器的只读调查能力，交回调查结论 |
| writer | 共享动作执行器的隔离写入能力，交回补丁及验证事实 |
| reviewer | 原审查阶段适配，交回裁决与发现，首次及续问均保存独立进度 |

## 页面

入口：角色管理 → 新建或编辑自定义角色 → **默认执行组合**。

提供六组可调整的推荐组合：通用执行、先讨论方案、结果交接、只读调查、隔离修改、专用审查。可分别调整执行方式、方案安排、结束方式，以及工具权限范围。选择组合时会补充对应允许挂载类型；角色列表显示默认执行方式与结束方式。

- 通用子任务的方案安排：自动判断、先讨论并审查方案、方案需要人工批准。
- 通用子任务的结束方式：完整交付，或交回结果由父任务集成验收。
- 专用适配交回各自结果；需要完整阶段流程时选择通用子任务。
- 工具范围可沿用执行方式的上限，或填写允许列表。空列表禁用业务工具，保留方案、结果提交、求助及只读协作控制入口。
- 每个子任务默认保存进度，无需另行开启 checkpoint。
- 默认流程供新派发任务使用，可由显式派发参数调整；角色工具列表作为限制上限。
- 基础系统卡继续保持模型绑定入口；默认组合在自定义角色中配置。

配置持久化到 `agent_role_cards.execution_defaults`。旧卡空值沿用原行为；旧客户端或 AI 更新未附此字段时保留原值，显式空字符串撤下组合。通用任务角色进入同一个角色目录，绑定的主执行模型、人设、技能、输入及输出契约参与实际执行。独立审查与视觉模型保持原有路由职责。

## 派发参数

只使用角色默认组合：

```json
{
  "tool": "child_task",
  "action": "dispatch",
  "params": {
    "role": "my_configured_role",
    "task": "调查指定接口并交回结论"
  }
}
```

显式选择通用流程与工具限制：

```json
{
  "tool": "child_task",
  "action": "dispatch",
  "params": {
    "profile": "task",
    "task": "阅读给定文件，讨论方案后交回结果",
    "execution": {
      "allowed_tools": ["local_file.read", "local_file.list"],
      "workflow": {
        "plan_mode": "cross_review",
        "completion": "handoff"
      }
    }
  }
}
```

`allowed_tools` 省略为继承宿主 profile；空数组为无业务工具。支持精确工具名与 `tool.action`，文件读取／写入／列表与动作协议的对应名称共用权限口径。Shell 权限仍受原角色命令边界限制。

实际权限同时受角色列表、父任务限制、宿主能力和当前资源授权约束。显式参数可以缩小角色工具范围，不能扩张它。固定专用入口使用自身流程默认值，同时应用角色工具上限，避免将通用任务的方案设置误灌入专用适配。

## 流程确实生效

`plan_mode` 传入原有主循环模式。明确选择方案交叉审查或人工批准后，finish 会核对实际已批准状态；不能仅展示选中项而跳过方案流程。auto 沿用原任务分流，不承诺完全不需要方案。

`completion=handoff` 保留明确验证、实际执行失败、已有阻塞及在途工作核对；不新增一次独立终审，并在结果中披露父任务仍负责集成与整体交付。`delivery` 沿用完整交付评估链。

收据增加兼容旧格式的 `handoff` 标记；缓存评估、正式提交和子任务结算核对它与已登记配置的一致性。交接成功使用 `handoff_accepted`，完整子目标交付使用 `delivery_accepted`，二者不混用。通用任务挂载角色时，角色自定义字段也在真实 finish 载荷上校验。

## 独立 checkpoint 与接收事务

- 派发登记同时保存执行配置、输入及 registered 快照，覆盖登记成功但执行器尚未进入的窗口。
- 动作与审查的独立快照保存在各自 `agent_child_runs.execution_checkpoint_json`，由 `execution_version` 做条件更新；不会借用另一成员的状态。
- 完整主循环继续使用原有 `agent_checkpoints`，保留已有终态与授权事务。公共成员查询读取其真实 checkpoint，避免一直显示初始 registered 状态。
- 动作型快照保存消息、动作输出、写入基线、测试证据、步骤、准备中的动作和累计时间。writer 恢复时保留原副本基线。
- 业务工具开始前先保存 prepared 状态。相同执行身份恢复时，读取及已登记消息可按既有身份处理；结果未知的命令和写入保留为中断事实，不自动重放。
- 消息进入上下文、可恢复快照和 `delivered_at` 同一事务保存；失败整体回滚，不能已核销却丢失恢复上下文。
- 终态提交同步标记检查点结束；晚到状态不能借旧版本覆盖新进度。
- `read_agent_result(view=checkpoint)` 可按原有同任务归属和分页范围读取；列表提供配置与 checkpoint 的事实摘要。

## 尚未覆盖的恢复边界

这版没有新增应用重启后自动恢复整棵协作树的调度器。原有孤儿执行收敛为 interrupted 的行为保留。公共 resume 仍有新关联尝试与角色契约限制，不能将它宣称为任意角色、任意阶段的一键原地恢复。

消息重试键仍包含发送执行 ID；本版验证的是同一执行身份中“发送登记后、观察检查点提交前”的恢复。跨父 run 的统一操作身份及旧成员重新归属尚未全部接通，不宣称跨重启的所有派发／发送都自动去重。父 Agent 应依据登记、结果和不确定动作事实决定后续工作，宿主不把未知外部操作自动当作未执行。
