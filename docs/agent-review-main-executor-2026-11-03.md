# 正式审查接入通用 Agent：桌面入口首版

## 执行与业务流程的边界

桌面宿主中的首次方案/阶段审查、审查成员续接和正式终审，现通过 `child_task::runtime` 调用实际 `main_loop`。`child_reviewer::main_executor` 只负责输入适配、只读取证边界和结果转换，不维护第二套模型/工具循环。

原卡槽选择、模型选择、角色材料、审查触发、单人/多人安排及结果处理继续使用原流程。审查成员仍登记为 `kind=review`，父任务收到原 findings 契约；终审收到原 ReviewResult。不能把“审查执行成功”理解为“被审查的交付通过”：有效的阻塞发现同样是成功回收的审查结果，原裁决流程继续处理它。

审查内部使用 handoff，固定方案/审查环节关闭，并使用 direct 入口，不再给审查员自动嵌套一份方案、入口分流或终审。正式交接仍经过公共执行器的检查点、契约校验和原子终态收据。模型请求、错误恢复及轮次行为改用公共主循环，不承诺与旧循环具有相同费用、时延和调用次数。

## 权限、证据和结果

- 通用循环不扩大审查角色权限。审查动作由原只读取证工具处理，并与父任务传下的工具允许列表取交集；写文件、任意 Shell、MCP 写入、嵌套实施及组合写入不会转到普通业务工具分发器。
- 对只读工具之外的实施契约、范围授权、重分流和方案更新返回明确未执行说明；否则这些顶层字段可能在工具调用后安排宿主核验命令，形成间接副作用。
- 证据读取复用原来源、会话归属和任务起点时间检查。Git 差异优先使用父任务保留基线，不以 HEAD 代替任务起点。
- 终审的 `verify` 只执行原流程已经绑定的方法，不从审查正文创建新命令。真实失败核验保留。命令开始前记录 pending；中断后结果未知时不自动重放，在结果中披露未确认事实，不伪造失败或通过。
- 使用原 JSON 解析、角色字段校验、宿主身份和多人定稿权限。覆盖缺口保留原来的两次修订后披露机制，不新增质量门禁。
- 回收必须对应本子运行、子会话的成功 trace、Done 检查点及同一正式收据；执行函数返回 Ok 不能替代交付事实。取消记录不能被晚到结论改写为成功。
- 审查自己持有同一根父任务的工作区锁引用；普通子任务内部派审时也沿委派链找到根持有者，避免误取消父任务。同树审查并行共用锁，不因第一个结束就释放其他执行的引用。

## 恢复与尚未统一的路径

审查程序及原结果契约保存在原执行快照，公共主循环另外保留自己的独立 AgentCheckpoint。桌面 `resume_child` 可把旧成员历史接到公共执行器；它仍通过原续接入口重核当前角色和权限。终审的内部传输记录不冒充可对质的 findings 成员，复审仍由原正式交付入口负责。没有新增整树跨重启自动恢复。

无桌面 AppHandle 的调用、MockRuntime 测试宿主，以及未绑定确切父 run 的辅助终审调用，仍保留旧循环适配。显式隔离 writer、历史 worker/writer 和只读补充答复也没有因本次迁移被删除。不能声称仓库中所有专用循环都已移除。

## 续接证据引用兼容修复

代码复核确认，新执行器克隆首次程序时继承非空 allowed_refs，使续接输出的新引用被首次清单拒收；旧 run_resumed_review 的 allowed_refs 为空，没有这项成员限制。

执行准备现在依据宿主登记的 resumed_from 区分首次与续接：仅续接清除旧输出引用清单限制，将有效程序保存到独立快照，同时在本轮任务末尾明确允许使用新取证或对质补充的引用。首次派发行为不变；原角色字段契约、任务时间边界、覆盖要求、只读权限及定稿权限保留。不把允许引用等同于证明证据内容真实，也不新增引用审批手续。

新增回归经过真实登记、执行准备、快照保存/加载和输出校验：首次清单非空时仍拒绝清单外引用；登记为续接后新引用可通过，结果与旧续接转换一致，缺必填字段仍拒绝，首次记录未被改写。人工审批与 Agent 方案审查的组合衔接不在本次修复范围。
