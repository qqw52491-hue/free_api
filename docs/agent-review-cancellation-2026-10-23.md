# 单成员审查停止与当前任务排除

日期：2026-10-23。

## 需求与实测触发

用户运行记录中的两批方案审查，step-5-preview 分别耗时约 172 秒和 346 秒，同批其他成员约 24～65 秒。用户明确要求可人工停止某一审查员，并在当前任务后续再次审查时排除该模型。

## 行为边界

- 运行中的方案、阶段和终审成员提供“停止并排除”。只向选定成员发送停止信号，主任务及其他在途成员不受影响。
- 排除依据模型配置 ID，范围绑定现有 `history_task_id`。当前任务后续派发、对质续接、阶段审查、终审和备用路径不会再次调用该模型；同任务恢复保留，新任务重置。其他已经在途的同模型成员不会被连带停止。
- 取消不算批准，不会撤回既有 blocking 或把人工操作伪造成审查员撤回。全体取消不能生成有效批准；部分取消则沿用其他实际有效意见。
- 已完成回执与点击交错时保留完成事实，仅记录后续排除；终审最终结果发布和停止入口串行核销，取消后迟到的批准不能重新打开该成员。

## 实现与成本

`review_control` 将精确审查 ID、会话、当前任务和模型绑定到独立中断信号，并转接原有整任务停止信号。只取消网络等待与沿用既有安全边界，不强杀正在执行的宿主验证进程。

排除集合保存于既有 checkpoint 的可选字段，无数据库迁移。控制面只原子更新该字段，不推进执行快照版本；正常保存和终态提交均在持有连接期间合并同任务的人工排除，防止运行中的旧快照覆盖用户决定。新任务不合并旧任务集合。真正的执行版本冲突仍按既有乐观锁回滚终态事务，不盲目覆盖更新版本。

子任务取消产出可被原信箱消费的终态回执并唤醒等待，不新建批准通道。取消回执记录已知耗时，未知供应商用量显式标记；不假造完整 token 使用情况。终审使用同一模型排除检查，并保留既有真实宿主复验失败。

新增成本为每个活动审查一个本地中断转接任务，以及派发和 checkpoint 保存时的本地排除读取/合并；没有新增模型调用、提示词验收义务或自动按耗时淘汰的规则。

- 一项联合终审聚合回归：取消不计批准、其他成员阻塞保留、全取消不放行。
- 前端真实组件与事件回归：按钮精确归属、请求失败展示、停止后其他成员继续、迟到事件不重开，以及新任务重置。
- Linux 本机完整 Rust 回归：1334 passed，0 failed，10 ignored，跳过 1 项 clipboard 测试。前端构建及相关四个回归脚本通过。

没有调用付费模型，没有停止用户正在运行的真实任务，也没有验证供应商服务端是否会在客户端中断后同步停止计算。新增后端命令需要重编译并重启应用后生效。
