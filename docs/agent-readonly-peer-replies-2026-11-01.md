# 同任务成员的只读追问与结束协调（2026-11-01）

## 当前接口

运行中的主 Agent / 通用子任务可使用：

```json
{"tool":"child_task","action":"ask","params":{"target":"同树已成功结束的成员ID","message":"为什么保留这个接口？","data":{"test_id":"reply-demo-01"}}}
```

worker / writer 的动作协议增加 `ask_agent`，参数仍放在 `params` 中。原有 `send_message` / `child_task.send` 继续用于给运行中的成员补充材料。未结束目标请使用原有消息通道。

受理返回 `request_id`、`reply_run_id`、实际 child ID、`read_only=true` 及登记状态。源 Agent 可以继续自己的工作，或等待自己的信箱；通用执行器用不带目标的 `child_task.wait()`，专用成员用 `wait_message`。答复完成后自动送回请求者，并通知主任务与原负责人。使用 `read_agent_result(child_run_id, view=result|history, offset, limit)` 可以在同任务范围内分页回查结果或既有历史，单页最多 8192 字符。

这是一轮关联到原成员的新只读执行，不是重新打开原实施任务。读取已有交接材料、必要文件或历史后回答；原成员的成功状态、交付内容、验证和审查裁决不改写。已结束 reviewer 可以被询问历史意见，但答复不是新裁决；更新正式审查仍使用原续问/审查入口。

## 能力与范围

- 只允许同一根任务内追问，所属主任务和发送方仍须处于有效执行状态。失败、取消、状态未知的目标不自动启动，由负责人决定显式续派。
- 答复使用原成员登记的模型，执行器复用共享动作内核。宿主只提供 `read_file`、`list_dir`、`read_message`、`read_agent_result` 和 `finish`；命令、写入、实施与再派发在动作层拒绝，消息和 Persona 不能扩大权限。
- 项目读取仍走当前父会话授权与原有原生读取入口。不创建第二个写入者，不复制新工作区，不恢复旧批准。
- 前次结果默认有界节选；原文按引用回查。worker/writer 使用已保存的历史，通用子任务读取原检查点中的目标、对话和已有摘要，不搬入审批或控制字段，也不扩大日志保存范围。
- 继续修改、重新验证或改变业务目标，仍由负责人安排。没有增加跨任务永久邮箱或全局自动接活。
- 沿用现有总并发和 worker 默认并发额度；未受理请求明确报容量错误，可在已有任务结束后重试。受理后的运行沿用原预算；本轮未新增单条答复取消按钮，主任务停止仍走既有级联取消和接收方中断通道。

## 可信登记与原子结束

复用 `agent_child_runs` 和 `agent_messages`，没有新增调度表。答复作为当前根任务的宿主管理 worker 登记，`purpose=readonly_reply`，`resumed_from` 关联被追问成员，保存原负责人和请求者的来源引用。

1. 同一个 SQLite 事务核对归属、主任务状态、来源执行状态、额度和重试键，并写入 `queued` 执行、问题及通知。重试认养原请求；同键换内容或目标明确报错。
2. 实际准备执行前再次以条件更新核对根任务状态；成功后转为 `running`。模型配置读取或控制通道不可用时，保存失败并回报，不留下无主 running 行。执行器异常退出由监督任务收敛为失败。
3. 结果、已有消息历史、终态和答复通知同事务提交。写入失败整体回滚，保留在途登记。重复或晚到的终态不覆盖已提交结果、不重复通知。
4. 主任务的验收前检查和最终提交事务均核对已受理答复。`queued` / `running` 以及结果尚未随父检查点回收的答复都算在途。
5. 请求登记与主任务成功终态通过同一数据库写事务串行化：登记先成功则暂缓交付；终态先成功则新追问不受理。提交时遇到新登记属于可恢复等待，不把主任务错误地标为失败或成功。
6. 原 `applied_at` 与父上下文检查点共同落账，表示父执行器已接收回执，不证明模型已理解。普通通知不变成必须回答的验收义务。

主任务失败或被取消时仍可结束，并保留未完成事实。应用恢复将遗留 queued/running 子执行收敛为中断，不自动重放模型或外部操作。信箱和结果记录沿用原会话清理；完整记录保留，完成只从待处理视图移出。

## 本地验证

7 项针对性回归覆盖：受理、执行完成及回执回收；真实线程同时登记与提交终态；跨任务、取消目标、已结束来源和重试冲突；结果与通知持久化回滚；启动失败回报；通用任务历史来源；本机 SSE 模型经真实动作内核完成追问，尝试写入、命令和再派发均未执行，原文件与原交接保持不变。

完整 Rust 回归 **1500 通过、10 项原有忽略、跳过真实剪贴板**（物理临时路径、系统 Python 3.9.6）；补充历史消息归属检查后，信箱相关 15 项回归通过。前端类型检查、生产构建和最终 Rust 构建通过。Python 3.15 的原有护栏测试文本差异见共享执行说明。

没有调用付费模型、重启桌面应用或改写真实会话。尚未做新接口的真实模型/UI 端到端实测，不宣称模型必然提出正确问题、正确理解答复，或任何并发场景都已被穷尽验证。
