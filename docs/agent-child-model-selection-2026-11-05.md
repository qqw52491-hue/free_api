# 子 Agent 显式模型选择

## 目标与范围

按用户确认采用默认继承、派发可覆盖、恢复不隐式换模型。不添加难度评分、失败次数升级器或自动模型池扫描。沿用当前执行器、角色和数据库模型配置。

## 实际规则

- `call_llm_phase` 在收到有效指令后保存本次实际模型到 `SandwichContext.last_execution_model`。DurableAgentContext 保存和恢复这一宿主事实；它不作为新的模型必填字段或提示词义务。
- 角色卡明确绑定模型 > 会话对应子任务角色槽 > 派发 `model_id` > 父执行实际模型。与人工绑定冲突时返回具体配置冲突，不启动任务，不静默改成另一模型。普通 task 不把父任务 executor 槽误当成子任务锁定。
- `child_task.models(offset)` 仅返回启用模型的精确 ID、显示名称与平台名称；每页 100 项，不包含连接地址或凭据。覆盖使用精确 ID，不猜测同名模型或供应商。
- `child_task/models.rs` 共用参数解析、选择、启用/存在性核对、目录和运行绑定。普通 task/worker/writer、兼容入口和专用 reviewer/isolated writer 派发接入。正式方案/阶段/终审通过共享 `route_for_role` 在无人工绑定时继承实际父模型。
- 新普通执行将选择及来源保存到派发快照、立即回执和后续状态视图；专用派发保存在原 params 快照。来源包括 role_card、role_slot、dispatch_override、parent_execution、previous_attempt、registered_execution；旧快照无法确定实际父模型时使用兼容路由并标记 legacy_parent_route。旧运行不迁移或猜补。
- 普通子执行固定 planner/executor/pro/flash/vision 的模型身份；图片或恢复不会偷偷换模型。选择的模型不具备处理图片的能力时，应按真实请求结果披露问题，而不是自动换一个模型。
- 原登记恢复从 agent_child_runs.model_id 读取模型，不按当前角色默认值重选。`child_task.resume` 是独立后续尝试：未指定模型时沿用原登记模型，指定不同模型时产生新身份；原结果、权限和来源沿用既有机制保留。派发身份本来覆盖完整参数，现在补回归确认 model_id 的变化也会区分身份。
- 旧 `resume_child` 专用续接仍保留原模型，不接受新 model_id；要换模型使用新的 child_task.dispatch 并引用旧结果。不会把换模型字段静默忽略。
- 终审规则版本升至 v19；有实际父模型时将其加入审查指纹，避免把不同继承模型对应的旧裁决直接作为新裁决复用。

## 已有配置边界

不更改主 Agent 本身的原有路由，也不新增失败自动升级。用户原本明确启用的审查跨家族选型及显式备用模型配置仍保留；它们属于已有人工配置路径。未据历史任务表现自动开启这些功能。

前端写入、探针、审查工位明确提供“继承父模型”；恢复默认删除对应覆盖，保留其他角色配置。已有持久化覆盖仍按原人工配置处理，不能猜测用户当时是否有意选择。角色卡明确模型仍优先。
