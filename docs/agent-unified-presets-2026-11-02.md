# 普通子任务统一执行与共享能力

本轮在已有通用主循环上收拢普通 worker/writer，不再为普通派发维护第二套动作执行器。

## 实际入口

- `child_task.dispatch(profile=task|worker|writer)` 都进入同一通用主循环，登记为 task 执行；原 profile 保存在派发输入及 purpose 中，表示角色预设。
- `child_worker` 是 worker 预设的兼容入口，`child_writer` 默认是 writer 预设的兼容入口。worker/writer 分别沿用 scout/writer 模型槽，角色专属模型仍优先。
- 角色的输入字段、输出契约、关注域材料、额外预载技能和测试命令仍参与派发；不会要求用户把 worker/writer 卡重新勾成 task。
- 没有自定义输出字段时使用通用 finish；有字段时沿用既有校验。共享 worker/writer 现在同样支持方案流程与 handoff/delivery。

普通角色使用主循环的 Skill 目录、按需手册加载、MCP 注册表及工具协议，不再经过旧 worker/writer 的固定命令白名单。默认工具范围仍与父任务限制取交集，项目目录授权继续生效；显式允许列表不因统一执行被放宽。Skill 预载列表不是共享目录的权限白名单。

## 工作区与正式审查

默认共享父工作区，普通实施的修改直接落在父工作区，不需要再 apply。
页面“默认执行组合”中的实施助手可显式选择 `execution.workspace=isolated`，使用既有隔离补丁服务和 apply 冲突核对；旧隔离产物与旧执行续接保留原协议。

正式 reviewer 继续承担裁决契约，不作为普通实施角色重新解释。只读收信/追问仍是受限的补充答复，不能因为普通执行统一就重开原实施。

页面普通角色均可配置方案与结果结束方式；工具限制保持高级设置。未增加 Skill/MCP 逐项选择或排除面板，未增加未使用的排除字段。

## 持久化和衔接

新执行复用通用任务的独立 AgentCheckpoint、消息投递事务、结果回收和正式终态事务。显式 resume 根据所属父会话读取原派发输入，保留角色、输入和执行配置，再按当前角色和父任务授权重新检查；不会读取其他会话的原输入。

明确传入或由角色提供的 test_command 在原始输入中持久化，并于执行入口绑定既有 ReviewContract 的可执行核验方法。保留现有验证执行和方法修订通道，不新增模型必须填写的状态字段。

## 当前边界

- 同一父任务的普通子任务可在共享工作区并行，父任务根据实际依赖协调修改；批量兼容入口逐项报告受理/拒绝。每个父运行仍受全局并发上限约束，普通 child_task 的 dispatches 数组尚不支持（可以逐次派发）。不同父任务的项目锁保留。
- 普通执行仍仅一层委派；子任务可调用正式审查及同树消息，不能再派普通 task/worker/writer。入口调查提示同步说明此边界。
- 旧专用 worker/writer 代码仍用于历史续接、只读答复或显式隔离补丁等兼容服务；不宣称所有专用代码已删除。
- 没有新增整树跨重启自动恢复，也没有验证真实模型自主使用共享 MCP 或页面交互。

## 验证

新增六项回归覆盖实际预设解析/公共执行选择、共享默认与显式隔离选择、MCP 默认可用及显式工具限制、通信动作别名一致、明确验证命令绑定、原派发输入续接与归属隔离。保留已有角色契约、事务、消息和栈回归。

完整 Rust 1427 通过、116 失败、10 忽略、跳过真实剪贴板；逐项核对 116 均为沙盒禁止本机 HTTP bind，无其他失败。前后端构建、类型检查及差异检查通过。未调用付费模型、未修改真实会话或重启应用。


## 审查统一的准备工作（未完成执行器迁移）

首次审查和历史续接共用独立的审查回执构造函数：审查字段解析、扩展字段保留、宿主身份与模型信息、角色契约校验均从专用循环中抽出。续接仍保留原有评分兼容行为；多人方案的定稿权限继续以宿主提供的值为准。新增回归覆盖宿主身份、扩展字段、定稿权限、引用、评分兼容及无效输入。角色工作区选择另增回归覆盖旧 writer 别名经角色配置后选择执行路径及显式共享覆盖。

本次未将正式审查或隔离实施派发接入通用主循环；审查与通用任务的登记类型、结果消费、续接、失败回执及阶段审查对账尚需端到端迁移。当时共享工作区普通子任务仍是串行；后续并发改动见下文。仅运行审查、审查续接、阶段审查和角色执行配置的定向 Rust 测试及 diff 检查；未调用真实模型或执行桌面 UI 验证。


## 同一父任务的共享工作区并发

普通通用子任务不再因其他子任务或后台任务运行而被一律拒绝，父任务也不因子任务运行而被一律禁止写入。主 Agent 按任务依赖协调并行和顺序；同文件或共享构建产物仍可能冲突，宿主不保证自动合并。项目目录授权和不同父任务之间的项目锁未取消。

共享项目锁由每个子任务分别持有，最后一个持有者退出才释放；旧代持有者不能释放已替换的新锁。每父运行全局上限仍为 6，通用任务不再单独限为 1；角色 max_concurrency 现已接入共享任务登记，按同一父运行、同一角色统计所有普通预设的 queued/running 执行，0 跟随总上限。普通 child_task 仍需逐次派发，worker/writer 批量兼容入口逐项派发。

新增测试覆盖多个通用任务登记与独立结果、并行子任务锁持有、旧代锁不能误释放。尚未做真实模型的并发派发、写入、取消、恢复、回收端到端验证；正式审查及显式隔离实施仍未迁入通用主循环。

## 并发派发的身份、批次恢复与角色配额修复

代码复核发现三项实际缺口：批量项仅改变 focus_paths/context_excerpts/test_command 时会共用旧去重键；单项派发覆盖父检查点里的完整批次；共享任务登记没有读取页面角色并发配置。

- 新派发身份取完整声明参数及批次项位置，先于实时角色默认值、工作区材料收集计算。同批完全相同的两项也有独立位置，恢复同一项则使用原身份。旧键只有在完整持久化输入一致、会话归属一致时才认养；不能靠旧键猜测不同兄弟项是同一次派发。
- 父检查点保存原始批次和逐项受理/拒绝回执。共享登记中断后从原批次恢复，已保存回执直接复用；登记成功而回执未保存时按原项身份查原记录，其余项继续派发。单个子执行器的恢复规则与整树跨重启恢复边界不变。显式隔离等专用适配中的未知副作用仍保留原人工核实路径，不因批次存在而自动重放。
- 角色配额核对与登记 INSERT 共用数据库连接互斥区，防止同时抢占最后一个角色名额；终态释放名额，其他角色和父运行分别计数，0 仍服从现有总上限。页面说明同步该口径。

新增四项确定性回归覆盖字段碰撞、重复批次项、旧格式归属核对、真实检查点保存/加载及登记后缺回执、角色名额线程竞争、queued 与终态计数及默认总容量。未调用付费模型、未重启应用、未修改真实会话；不宣称已完成真实模型并发写入验证。

本轮定向 Rust 共 103 项通过：子任务 21、检查点 58、执行配置 12、角色执行配置 9、原登记配额 1、入口 future 体积 1、默认 2 MiB 线程栈收信/检查点 1。检查点组另有 19 项失败，逐个失败块均定位为 retirement_tests.rs 本机 HTTP bind 的 PermissionDenied，无其他失败；没有重跑完整 Rust 套件。最终四项新增回归复跑、cargo check --tests、后端 build、前端类型检查/build 及 git diff --check 通过。
