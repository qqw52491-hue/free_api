# 子任务上下文入口与预算分区

## 依据与范围

真实会话 fd87e89f 的两次阶段审查 evidence_excerpt 均为 6000 字符；5205 字符的原始目标、待办和临时产物清单挤掉后续执行证据目录及 diff。代码复核还发现普通任务重复渲染 custom_inputs，Reviewer 将消息序列化到目标文本后，又套入允许实施和委派的普通系统提示。

## 模块边界

新增 src-tauri/src/agent/task_context/：

- mod.rs：统一对外入口，仅暴露需要的组装函数。
- dispatch.rs：普通任务的目标、角色/输出契约、派发材料、验证命令、父证据目录。显式输入独立保留，不依赖可选关注域是否存在；专项采集不再重复渲染同一批 custom_inputs。调查参考单独注入，角色名称不授予能力。
- review.rs：审查系统指令与用户/历史材料分开组装，使用统一工具调用及 finish 协议；阶段证据使用独立区块预算。
- budget.rs：按 Unicode 字符计入标题和省略提示；每个区块单独裁剪，不再依靠整个包统一截尾。diff 可保留尾部，其余材料保留开头并提供回查提示。
- visibility.rs：使用现有 ExecutionConfig.permits 和别名规则决定可见工具，展示限制及来源是启动时快照；不负责授权或扩大权限。
- tests.rs：预算、字段保留/去重、角色与材料分离、权限别名的确定性回归。

阶段预算：目标摘要 1200、待办 900、补充证据合计 2000（各条分配）、关注域 500、diff 1100，留余量给固定说明。长目标不能再占用执行证据和 diff 的分区。完整父任务目标通过独立消息传递，不受该 6000 字符证据包限制。目录只是入口，扩展原文继续经既有 output_id、步骤目录和任务树工具读取；分区不是已覆盖或已通过的认证。

## 接入及权限

普通 task/worker/writer 的共享派发走统一普通材料入口；显式输入、验证命令、父证据目录和角色交付契约保留。角色关注域采集仍由原 context_collector 提供，权限不会因换角色而扩张。

Reviewer 准备阶段仍持久化原 ReviewProgram 和原始消息；原 system 指令进入实际系统上下文，用户及历史材料以作用域标记传递，不再把整份 messages JSON 当成任务目标。主循环的 Reviewer 分支不注入普通实施/委派菜单、角色池或 MCP 菜单；仅说明当前审查职责，内部四项流程开关继续留在检查点，不再作为模型必须理解的正文。

限制业务工具的普通子任务展示允许的工具/动作及宿主核验说明；MCP 索引和内置紧凑索引按有效配置筛选，不把完整菜单当作执行授权。现有每次调用授权、组合叶子授权、Reviewer 只读适配和目录围栏保持原样。未重新实现权限白名单。

方案、阶段和最终审查仍保留各自材料采集与结果协议；普通最终文本、已有工具索引和历史来源不强制统一成同一种内容。终审规则指纹升至 v17，避免把旧上下文规则裁决直接当作新规则裁决复用。

## 验证与限制

新增四项确定性回归覆盖 10000 字长目标、超长待办/清单、独立证据目录与 diff、Unicode 极小预算及大量补充块、普通显式输入不被专项材料遮蔽、系统与用户/历史分离和权限别名。扩展真实假模型 HTTP 派发回归，核对长完整父目标作为独立消息送达。旧阶段证据上限及 diff 尾部回归继续通过。

不新增数据库字段。旧检查点、首次/续接结果契约和旧无桌面宿主适配保持兼容；已在运行的旧正文不主动重写。未重启桌面、未修改真实会话、未调用付费模型。预算与材料传递回归不能证明模型必然读全或正确判断测试覆盖，真实模型/桌面交互仍需另行实测。

## 复查后续修复：项目规则、有效权限及预算调剂

复查探针确认 Reviewer 新系统分支漏拼已读取的 AGENTS.md/HUB.md，且权限正文把 allowed_tools 配置上限当作可执行集合：例如 child_task 被列入正文，而只读适配器拒绝它。本轮 review_entry 将工作区及自定义规则作为公共上下文保留；权限正文和紧凑索引都由同一 reviewer_tools 投影生成，结合配置、只读适配、预算和契约复验能力。未更改执行授权内核。终审指纹版本升为 v18。

阶段 6000 字符预算现改为先保留各区块配额，再把空闲容量借给仍有内容的区块。短目标不会浪费本可用于 diff 的空间；长目标也不能剥夺其他区块保底。这是确定性的字符分配，不是模型或语义质量判断。

普通任务增加 16000 字符软预算：目标、角色/输出契约、派发方明确输入与验证命令原样保留，可选 specialized_context 使用剩余空间。必要输入本身超过软预算时保留输入并披露扩展材料未内联，不以裁剪明确要求来伪造达标；这不是全局模型窗口的硬上限。

补充 read_agent_result(view=dispatch_input) 只读分页视图，准确指向持久派发快照里的 params.specialized_context。原因是原 view=checkpoint 在任务启动后投影到主检查点，反而不再返回原始派发输入。新视图使用原有任务树归属校验，主任务没有子派发快照时明确报不适用，不返回其他结果冒充。

新增四项回归：公共项目规则及权限交集、空闲预算调剂且必要区块不丢、普通任务软预算及源引用、真实 SQLite 派发输入在独立检查点生成后仍可读取且越域拒绝。此前新增回归和原始交付/恢复/只读回归继续保留。未运行付费模型、未重启应用或改写真实会话。
