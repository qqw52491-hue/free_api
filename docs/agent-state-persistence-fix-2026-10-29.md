# Agent 状态与持久化修复（2026-10-29）

## 修复内容

- SessionRunGuard 收尾按精确 run_id + session_id 查询已保存的终态，再采用本次状态机终态与取消记录；不再把 Result::Ok 等同于业务成功。失败/取消的 RunRecord、channel-run-done 和通知保持一致，已提交成功也不被后续收尾错误改写成失败。
- 没有取得任何本次终态时明确记为未确认完成的运行失败，不静默标成功；终态后的迟到进度不会重新进入等待。终态事件被收集在守卫内部，直到真正收尾才发布 RunRecord 终态，不提前释放同会话在途保护。
- 普通检查点与回执消费提交使用候选副本，只在 SQL/整笔事务提交成功后发布新版本。SQL 失败、回执更新失败、COMMIT 失败都保留调用方原对象。
- 删除危险的“拿最新版本号重交旧整包”合并重试。真正的版本冲突明确返回未覆盖/未核销；调用方须重新读取并基于最新状态重新应用有归属的操作。不会覆盖新人工决定、新批次、新任务身份或终态，也不会复活已删除检查点。
- 人工停止审查的排除集合仍走既有独立增量合并，不推进执行版本；未新增语义门禁、模型字段、审查次数或模型调用。
- 阶段审查派发后、敏感访问确认登记处不再丢弃保存错误；明确传播失败，由主循环现有错误收停兜底处理，敏感命令仍未执行。
- 少量 AppHandle/SessionRunGuard 签名改为 runtime 泛型，以便用 Tauri MockRuntime 测试正式失败、取消与收尾函数；生产默认仍为 Wry。
