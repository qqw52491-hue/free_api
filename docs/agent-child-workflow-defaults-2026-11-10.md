# 子任务默认流程设置

新增独立页面「子任务默认流程」，侧栏入口为「子任务流程」，角色工坊顶部也可进入。

页面先选择交付责任，再选择方案模式；四个固定环节折叠在可选设置内。展示通用 task 与调查/实施助手各自的默认交付效果，包含保存、失败反馈、恢复原有默认及窄屏布局。

## 生效规则

- 配置缺省时保持既有行为：task 完整交付，worker/writer 结果交接；未显式选择的流程按原策略处理。
- 新派发的普通任务，在角色默认值与本次派发输入合并后，仅用公共设置补充未指定字段。角色流程和交付方式增加明确的「继承子任务默认流程」选项。原角色的显式设置不迁移、不改写。
- 公共设置明确要求人工批准时，角色或派发参数不能将其降为自动或交叉审查；发生冲突说明原因，不启动该次新派发。人工仍可修改公共设置。
- 工具权限、模型、主任务流程不进入这份配置。正式 Reviewer 和隔离补丁不套用普通任务默认流程。
- 已登记执行、回执重放、实际续接和显式追问不重新套用新公共默认。新任务的有效配置与输入仍经原登记入口保存，原检查点和恢复协议不改。
- 配置保存在应用数据目录的 `child-workflow-defaults.json`，不写入项目源码。缺文件即原有默认；损坏/读取失败记录运行日志并回退原策略，页面明确报错。没有新增数据库表、模型调用或语义检测器。
- 设置之间不兼容（例如先讨论方案但关闭正式方案）时报告具体配置冲突，不猜测用户希望覆盖哪一项。

## 实现链路

`ChildWorkflowView.vue → get/save_child_workflow_defaults → ChildWorkflowDefaults::load/save`

`dispatch_child_task → 原派发准备、当前/旧格式登记查重与模型选择 → 新普通 dispatch 读取公共默认 → apply 补充缺省字段 → 原权限/登记/主循环`
