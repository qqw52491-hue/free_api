# 任务可写目录起点与终审差异

本次沿用现有逻辑任务身份和检查点，不增加目录登记工具、模型必填字段或审查轮次。

## 行为

- 新任务保存主工程和配置中附加可写目录的起点；只读参考目录不拍摄。
- 每个起点覆盖所登记的物理目录。同一 Git 工作树下不同子目录分别保持覆盖范围，不能因仓库相同而遗漏另一子目录的用户原有修改。
- 运行中增加目录、或从只读切换为可写：配置刷新入口先追加起点到检查点，再发布运行时权限。撤销再授权不重拍同任务起点。
- 续跑、换模型、中途提交保留原起点；新逻辑任务清空旧起点。续跑入口不再无条件创建新的主工程快照。
- 终审独立对比各目录起点与当前状态，包含已提交改动、再次修改的脏文件、未跟踪文件和删除路径；修改登记仅作辅助线索，差异不证明修改者。
- 终审临时文件集合只来自任务内已登记路径与明确交付对象，不再按 mtime、目录深度或数量遍历临时目录。宿主日志的存储和按需查询不变；明确交付的日志仍参与检查。
- 各目录变化按绝对路径汇总，参与终审和交付收据指纹。正文展示有界，完整文件内容仍流式参与指纹；Git 链接按链接文本取材，不沿链接读取正文。

## 持久化和权限

复用 `AgentCheckpoint.task_additional_git_baselines`，键为物理目录，兼容此前的仓库根键。动态授权只追加这一字段，不改任务、阶段和工具回执。检查点保存时，在相同数据库锁内合并相同任务已持久化的起点，避免旧内存副本覆盖动态追加项；其他状态继续使用原乐观锁，不重试覆盖冲突。

目录撤销、物理路径替换、起点对象失效和旧任务缺少起点均如实披露。缺少起点不以当前状态补拍，不按时间扫描冒充完整差异，也不因此新增交付门。非 Git 工程沿用已有的有预算影子快照；无法建立时使用已登记/明确交付路径并披露范围。

这不是任意 Shell 的进程审计或操作系统沙箱。任务范围外、远端副作用、被 Git 忽略且没有登记或明确交付的文件不保证自动发现。原有真实执行失败和审查缺陷仍保留。
