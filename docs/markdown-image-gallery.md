# Markdown 图片展示

回答仍使用标准 Markdown，无需新增模型字段或改写聊天历史：

```markdown
![说明一](https://example.com/image-a.png "可选标题")
[![说明二](https://example.com/image-b.png)](https://example.com/article)
```

- 连续的独立图片段落合并为图片组，最多三列，并随内容区域宽度换行。
- 标题优先作图片说明，否则显示替代文本；链接包裹图片时保留网页来源。
- 点击缩略图放大，支持按钮/方向键切换、Esc/关闭按钮关闭。原生 dialog 管理模态焦点。
- 失败图片显示提示，用户可手动重试。无查询参数的 HTTP 地址在重试时附临时缓存标记；有查询参数的地址保持原样，避免破坏签名。预览使用本次缩略图实际请求的地址，原始正文不改写。
- 打开的预览保留其图片快照，后续流式正文追加图片不改变正在浏览的序列。
- 图片混在正文、列表、引用和代码示例中时继续走既有 Markdown 渲染；音视频不转成图片组。其他图表、公式和代码功能不变。

图片组的 Vue 绑定地址单独校验协议，不接受可执行 URI 或非图片 data URI；普通 Markdown 的 HTML 清洗保持原样。本地绝对路径复用已有 `convertFileSrc` 映射，不扩大资源访问权限。相对路径仍按现有页面基准解析，不推断项目根目录。

模型配图是可选建议：已有搜索候选、用户文件或工具产物且有助于说明时使用，不编造地址、不要求额外搜图，也不新增交付义务。搜索候选不等于图片内容已核实；远端拒绝访问、签名过期等情况仍可能导致加载失败。

验证：

```sh
node scripts/test-markdown-images.cjs
npm run build
```

本地合成浏览器页面另行验证三图并排、340px 窄栏换行、放大/切图、Esc 关闭及焦点恢复、失败图片恢复后手动重试成功。测试不调用模型。尚未验证打包桌面端的本地文件加载或真实供应商的配图行为。
