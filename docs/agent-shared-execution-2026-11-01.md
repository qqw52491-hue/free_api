# 子 Agent 共享执行内核（2026-11-01）

## 本轮结果

将重复的执行循环迁移到公共驱动，保留角色、工具能力、隔离工作区与交付契约。不是把所有角色塞进完整主任务流程，也不是仅修改角色提示词。

```text
execution::run：推进一轮 → 保留独立状态 → 继续 / 结束 / 返回错误
  ├─ main_loop::turn：主任务与通用子任务的可恢复阶段
  ├─ execution::actions：侦察、隔离写入共享的模型—动作—观察执行器
  └─ 审查轮次：取证、输出契约补正及续问的阶段适配
```

主任务和通用子任务原有通用执行能力继续复用；主循环的一轮处理移到 `main_loop/turn.rs`，状态通过 `MainExecution` 显式传递。原有阶段逻辑、预算、检查点、人工授权、终审和交付收据保持原判定，没有复制第二套主循环。

侦察和写入不再各自维护 `run_worker_loop` / `run_writer_loop`。`run_worker` / `run_writer` 只装配配置、准备材料，并把共享执行结果转换成原来的回执。共享动作内核统一处理模型请求、流事件、消息注入、调用诊断、动作解析、观察预算、取消和错误归类。共享动作协议位于 `execution/protocol.rs`。

审查首次执行及续问的迭代也使用公共驱动；审查取证、契约补正、发现编号和有效裁决仍由审查适配处理。没有把 reviewer 的结果改成普通任务的 finish，也没有增加其权限或运行中信箱入口。

## 按能力装配，按任务验证

- 侦察能力仍调用受限读取和命令执行入口；不能因收到消息而获得写入能力。
- writer 仍使用独立副本、写入留底、补丁回收和冲突检查，不直接修改父工作区。能力由宿主代码装配，不读取模型声明来扩权。
- 角色卡、Persona、自定义输入约束与输出契约保留。父子身份、消息投递与原结果回收机制不变。固定目录不再绑定角色，详见下节。
- writer 的 `test_command` 改为可选；参数类型检查、工具说明和默认提示同步。角色默认测试命令仍会按原机制装配，指定的命令仍要求执行；实际失败证据保留。
- 未指定或未执行测试时返回 `not_run`，不会合成“通过”。父任务仍须依据真实目标、已有要求和证据决定适用验证。缺少预先填写的测试命令，不再单独阻止派发。
- writer 合入回执区分未配置、尚未通过、实际失败和副本已通过；已通过时要求核对证据覆盖的版本，适用可复用，有差异或缺口再补验，不再统一要求机械重跑。
- 方案讨论、独立审查和主任务验证沿用现有模式、分流与契约决定适用性。没有新增绕过用户批准、有效阻塞或明确验收要求的模型开关。

## 角色卡不绑定项目目录

按用户要求移除角色 Hard Scope：管理页表单、卡片徽标、AI 生成与迭代协议、后端角色字段及派发自动注入均已删除。角色的适用场景提示继续保留为说明，不再自动拆成 writer 的 `focus_paths`；具体文件来自本次派发，项目授权及实际工具的路径边界保持原实现。

旧库 `agent_role_cards.hard_scope` 列只保留存储兼容，不再读入角色属性、显示或执行，不需要改写真实历史卡片。旧客户端传来的该字段被忽略；保存其他角色属性不覆盖旧列。模型、启用状态、并发额度、技能和输入输出契约仍走原通道。

新增临时数据库回归覆盖旧目录值及旧客户端字段失效、其他字段映射不偏移、作用域提示不生成文件路径，29 项角色相关回归、前端类型/构建检查通过；移除目录属性后完整 Rust 回归 1493 通过、10 项原有忽略、跳过真实剪贴板。

## 没有扩展的范围

仍只允许一层通用任务委派、同一父任务一次一个共享工作区通用子任务。未增加侦察递归派发、writer 自行创建下级 writer 或跨任务全局调度。已结束成员的明确只读追问可启动关联答复轮，原实施任务不重开，详见 [只读追问与结束协调](agent-readonly-peer-replies-2026-11-01.md)。共享执行器不代表共享上下文、权限或运行状态。

专用模块保留的是能力实现、材料装配和结果适配，不是旧的独立模型执行循环。后续不必为每种角色复制一次消息、模型请求和动作反馈代码。
