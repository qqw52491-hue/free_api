## 调整

终审、子审查、子审查续跑共用 `review_stream`：

- 非空正文和思考片段刷新静默计时；SSE 保活、空 delta 不延长等待。不凭内容语义猜是否有进展。
- 首个输出与后续静默沿用既有模型时限：一般 60 秒、慢思考类 120 秒，`FREE_API_REVIEWER_TIMEOUT_SECS` 可覆盖。没有任何输出时，一般终审仍是 60 秒加一次 120 秒等待。
- 既有 `FREE_API_LLM_CALL_BUDGET_SECONDS` 调用总预算保持不变，默认 240 秒，包含传输重试与退避。持续输出不会刷新总预算。外层静默重试是另一轮有界调用，240 秒不是整个审查的总时长；总预算耗尽不再同参重试，但原有用户配置备用审查通道保留。
- 仅审查调用使用模型配置副本，使底层 HTTP 总超时与调用预算对齐，避免活动守卫仍被原 HTTP 120 秒切断。共享客户端 15 秒连接时限、普通聊天请求和主执行模型配置不变。
- 首输出超时、输出后静默、总预算耗尽分别记录；包括 elapsed/idle/首输出时间、观察到的正文和思考字符数。错误日志分别保存至多 4000 字符前缀，说明可跨传输尝试及是否截断；usage、真实尝试数未知时不编造。部分 JSON 不进入审查判决解析。
- 子审查复用已有 `agent_stage_marks` 记录请求与输出活动，输出打点最多每 5 秒一次，回收器按最近活动判断 reviewer 是否失联；旧行无标记回退开始时间，异常未来时间不当作活动。writer/worker 的原规则不变。回收宽限覆盖最长静默等待。
- 用户中断继续返回原始中断信号，不触发超时重试。审查失败仍不等于通过，不解除具体阻塞项或冻结验证。

未改取证步数、模型输出预算、方案/终审验收规则、主循环状态机、会话级运行预算或看门狗；超长的整场审查仍受这些既有上限约束。未新增配置面板、数据库字段或“有进展”语义检测器。

## 本地验证

- 6 项虚拟时钟测试：无输出、正文/思考持续至 160 秒、输出后静默、保活与空 delta、持续输出触及 240 秒总上限、取消和诊断采样上限。
- 本机 SSE 假服务：原 HTTP 配置为 1 秒，持续输出超过 1 秒仍在单次请求内成功；另一次流输出后用户停止，立即返回中断且不额外请求。模型配置原值不变。
- 临时 SQLite 回收回归：运行两小时但刚有活动的 reviewer 保持运行；失联、旧格式和未来时间标记仍回收；worker 原规则保留。
- `cargo test --offline --lib -- --skip clipboard`：1169 通过、0 失败、10 项原有忽略、1 项剪贴板过滤；`cargo check --offline` 通过。本地绑定端口需要沙箱授权，测试未调用外部付费模型。

这些测试证明资源时限和取消机制，不证明原 WorkBuddy 请求一定能恢复，也不证明模型会给出正确结论。没有可见输出的排队/隐藏思考仍会受静默时限影响。应用需重新构建并重启后端才能使用本次改动。
