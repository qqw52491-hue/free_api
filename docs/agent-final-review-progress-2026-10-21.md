# 终审进度可见性

## 问题与范围

用户实际运行中，终审等待数分钟但主界面没有可用的过程状态。源码确认：终审只有初始
`action_phase` 通知，取证环原来忽略所有流式活动；前端保存阶段文字，但主要对话区域未展示它。

本次仅为终审添加观测与展示，不修改审查要求、裁决规则、取证预算、模型选择、重试次数或超时配置。
不增加模型请求，不将调用失败或活动心跳解释成审查通过。

## 实现

- 后端终审共用入口广播 `finish_review_progress`，包含独立尝试 ID、成员键、角色与模型、
  实际阶段、累计耗时、逻辑请求序号、已用取证步数与预算、收到的片段字符计数。
- 等待请求或宿主验证时每 5 秒刷新一次。定时器和被观察 Future 同生共死，返回或取消后不遗留心跳任务。
- 首次收到思考/正文片段只报告已收到响应与字符数，不转发思考、原始正文、工具参数或源码。
- 取证、验证、超时重试、格式纠正、预算收敛和最终裁决均有阶段通知。
  最近一次超时/格式异常在再次等待时仍保留，防止瞬间状态切换让提示消失。
- 主对话区域上方挂载独立状态区，单审和多成员分别显示。展示阶段与计时，不生成伪百分比。
- 前端按成员/尝试身份更新，隔离其他成员，忽略已终结尝试的迟到活动与旧运行事件。
  备用尝试覆盖同一成员显示；新运行清空旧卡。运行结束后不再展示活动动画。
- 阶段变化进入已有过程日志；每次心跳只更新卡片，不刷日志。

## 验证

新增 5 项 Rust 回归：无原文的活动计数、异常提示保留与失败终态、静默请求心跳、取消后无孤儿心跳，
以及本机 HTTP 假模型经真实终审/事件入口走过格式纠正、取证、最终判决；断言没有新增模型调用。

- 终审相关 Rust 回归：60 通过。
- 完整 Rust 回归：1262 通过、0 失败，10 项原有忽略；跳过 1 项会覆盖系统剪贴板的测试。
- `cargo check --offline --manifest-path src-tauri/Cargo.toml` 通过，存在原有编译警告。
- 前端新回归执行实际 composable 事件处理和 Vue 模板渲染，覆盖等待/取证/纠正、心跳不刷日志、
  成员隔离、备用/迟到回执、停止和新运行清理。
- 既有完成展示、任务恢复、子任务展示与流式预览回归通过。
- `vue-tsc --noEmit`、Vite 构建和 `git diff --check` 通过。
- 使用真实 Vue 模板的合成三成员数据进行了独立浏览器布局预览；不是桌面应用真实任务截图。

## 限制与生效

本次实现针对终审；未改造方案审查或阶段审查的既有展示。进度属于运行期 UI 观测，未新增数据库表，
也没有实现应用重启后的历史进度卡恢复。完整诊断仍在原有审查日志中。

未调用付费模型，未自动重启应用或续跑用户任务。需重新编译并重启后端，配合更新后的前端生效。
不宣称提升模型速度、供应商稳定性或判断质量。本次变更未自动提交或推送。
