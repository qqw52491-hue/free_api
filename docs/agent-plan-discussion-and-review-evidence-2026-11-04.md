## 实现

- 共用 plan_discussion_required：显式关闭优先，成功的 technical_plan/expert_panel 判决选择讨论；fallback 不当作已判定复杂。沿用 checkpoint 原字段、submit_plan、原批次/反驳/人工仲裁，不新增复杂度检测器、计数器或审批轮次。
- Auto 提交复杂任务方案不再因无拟改文件 FastPass 免审。写入与正式交付复用原方案门，已选讨论须有正式方案及有效审查收口；阶段批准可在只读交付前落账。修正 Auto 指引和只读 target_files=[] 说明。
- 调查取证仍开放，不按 Shell 内容猜测调查何时结束；主模型按方案指引先调查再讨论。宿主核对可判定的方案/批次事实，不验证模型是否“想充分”。降低审查强度仍须走既有人工渠道，retriage 不自批放宽。
- 复杂任务方案获批后，Auto 可按已选 milestone 策略运行阶段审查；只读 todo 完成转换也可触发。完成转换在更新待办前比较，重复已完成项不会反复派审。显式关闭、none、预算、在途和原有效阻塞继续生效。
- Reviewer 新增分页步骤目录、分页任务树状态、分页子执行结果查询。步骤按 run_seq 导航，输出以 output_id 回查。后代读取必须携带本树 run_id，宿主按持久化 parent_run 链绑定会话；不开放任意 session_id。
- get_step_output 与 read_step_output 共用审查读取实现。终审注入方案状态和有界子执行目录；完整子树状态及结果参与指纹，后页结果变化不复用旧通过。终审自身记录排除，避免自触发缓存变化。
- 无绑定父 run 的旧辅助调用对目录查询明确报不可用，不猜归属；原本会话回执读取能力保留。没有新增证据阅读次数或覆盖度硬门。
