# Agent 工具调用与原有修改保护修复（2026-10-27）

## 实测与归因

只读抽查本机 2026-10-27 的 17 条运行、270 条步骤。与主运行会话和时间范围关联到 279 条主模型调用记录，其中 3 次解析失败随后恢复；一条请求错误出现在取消且无步骤的任务里，不能据此认定供应商故障。10 个子任务均成功结束。failed 步骤中包括权限确认、转入审查、真实编译失败，不能把失败计数全部归为调用故障；此样本未证明存在持续空转。

运行 `32580d87` 的任务开始基线已经记录 `config/` 下 5 个文件有未提交修改，后段 pipeline 却成功执行包含 `git checkout -- config/` 的命令，随后该目录修改状态为空。最终检查点没有这条破坏命令的人工确认。此证据证明任务前已有未提交内容被还原，不证明内容的重要性或不可恢复。本报告不包含配置正文、凭据或其他项目的私有路径。

当前源码的两处缺口相互独立：外层 Shell 抽取器没有遍历 pipeline 的 commands；目录还原目标又被拿来与单个脏文件精确匹配，匹配不到被当成干净。组合指令的写入分类也遗漏了实际子动作。

另两类实际重试：原始附件路径不在工具允许范围，模型随后猜文件名或资源入口；把 todo_update 当成独立工具、把原生 project_resources 的动作写成 MCP 斜杠名称。

## 修改

- 将原有 Git 破坏命令保护下沉到实际命令执行前；主 Agent 的单步、流水线及并行/嵌套计划树传递同一份派发授权快照，在真实叶子解析完参数后检查。待确认指纹回写原有 checkpoint 字段，不新增确认协议、数据库表或模型必填字段。流水线保留已执行结果，失败后的后续步骤不执行；并行仍保持原有 allSettled 语义。
- 用 Git 自己的 pathspec 解析匹配目录、通配符及 top/literal 等形态，结合 index/worktree 的实际改动清单对账。任务前已有修改不能因进入计划或又被 Agent 写过而获准丢弃。正常的本轮改动清理和干净目标保留原有通道，明确人工确认后可原样重试。
- 基线捕获采用 NUL 分隔路径，分开比较暂存区和工作区，避免中文/空格/换行被转义或 trim，也避免两处变化相抵时被当成干净。兼容严格可解码的旧 C 引号路径，保留原始检查点键；对齐物理目录别名，不跟随最终被 Git 操作的符号链接。
- 组合指令按真实子动作分类，纯读批次仍然只读，写入批次进入已有变更流程。
- 附件首次注入就保存内容寻址的会话临时副本，发送真实可读的 view_image 路径，不再把应用私有原路径写成工具可读路径。保存失败时保留原图并说明失败，不编造副本；复用现有路径权限和观察流程，不开放应用附件根目录。
- 说明 todo_update 是顶层数组字段；澄清原生工具的 params.action 与外部 MCP 名称。未知调用给出对应的正确形态并说明未执行，不猜测执行或新增隐式别名。

## 成本和边界

无额外模型调用、阅读量约束、步骤计数器、语义进展门禁或模型配置修改。Git 目标查询只用于识别出的破坏命令；附件副本增加本地保存工作，复用已有内容寻址文件。

这不是任意 Shell 程序的完整语义解释器；复杂脚本、间接执行及所有外部插件的安全边界不在本次覆盖证明内。敏感访问规则及现有人工确认策略未放宽。本轮未重放真实任务、未改写真实数据库/日志、未恢复其他项目的历史内容，未调用付费模型，未验证实际供应商重试率或桌面 UI。
