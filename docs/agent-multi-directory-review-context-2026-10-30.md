# 多目录执行事实与审查取证

本次只修改目录信息的传递和审查员的现有读取入口。一个任务仍可操作多个已授权目录，不引入唯一活动工程、目录切换步骤、新审批或模型必填项。

## 已确认缺口

- Shell 的结构化回执有 cwd，但审查摘要会移除结构化元数据，正文没有明确保留启动目录。
- 文件读取已有 resolved_path，写入、局部修改与目录列表缺少同等信息；通用审查摘要优先取 message，搜索无命中时也可能丢掉 resolved_root。
- 执行者已经支持附加目录，方案/阶段审查和终审使用的 review_tools 仍仅允许主工作区和会话 tmp。文件证据引用的宿主摘录也有同一处范围缺口。

## 修改后的行为

1. 文件读取正文显示实际路径，写入、修改、列表回执补 resolved_path，写入/修改视图同步提供。保留原 path 字段。
2. Shell 正文及失败重试诊断明确 cwd 为进程启动目录，不推断命令内 cd 之后的位置。通用审查摘要保留 cwd、resolved_path、resolved_root；批处理节选保留 Shell 启动目录。
3. 审查工具读取当前会话已配置的附加目录，文件、目录、定向搜索、只读 Shell/Python 和证据引用摘录共用该范围。复用原权限表，不新增授权来源；每次请求重新读取权限，撤权生效，目录链接改指向不迁移旧授权。
4. 方案/阶段审查与终审收到默认工作区、会话临时目录和附加目录清单。附加目录使用绝对路径。省略 path 的旧搜索仍只搜索主工作区和会话 tmp，不自动扩展到所有工程。
5. 默认工作区和 Git 基线保持原样，基线说明标出适用工作区。专用 git_diff/git_log 仍只针对默认工作区；附加目录没有因此获得独立任务起点快照，不能把其普通 Git 差异冒认成本任务增量。

目录权限与输出路径只说明可访问范围和操作对象，不证明修改归属、业务完成或验证充分。

## 本地验证

新增 7 项回归，另增强既有流水线及失败重试断言。覆盖同名文件、带空格目录、只读/读写附加授权、无匹配搜索范围、默认搜索范围不扩张、跨会话/错误主目录拒绝、撤权、链接改指向，以及真实方案审查/终审调用链取证。

相关 155 项测试通过：review_tools 18、local_file 15、local_shell 24、child_reviewer 12、reviewer_gatekeeper 86。后台测试使用隔离的临时 XDG 数据/配置目录；默认应用数据位置在本地只读环境中导致的两项失败已在隔离环境复测通过。cargo check --offline --tests、cargo build --offline 与差异空白检查通过。

未调用真实供应商模型、重启桌面应用或改写真实运行记录。此修复不保证模型必然选择正确目录，也没有新增跨仓库基线、批处理退出码配置或浏览器能力。
