# 终态文件检查按逻辑任务与交付对象取材

## 问题与范围

旧异常扫描从整个会话历史读取 tmp，历史空后台日志也会阻断 mechanical_only 的直通路径，造成只读问答追加模型终审。修改只针对终态文件取材；没有迁移、删除或重新归档日志，没有新增模型必填字段、数据库表、任务生命周期或审查轮次。

## 实现

- 沿用主循环已保存的 task_started_at、task_git_baseline 和检查点恢复语义。history_task_id 同任务恢复保留、新任务重新创建，不以 run_id 或当天日期重置任务边界。
- 终态文件候选来自既有基线差异、任务起点之后的会话 tmp 有限扫描、排除 inherited_side_effects_count 之前历史记录后的实际写入路径，以及 finish 明确提供的交付路径。变化只是候选线索，不证明修改者或业务目标完成。
- 通过既有 agent_background_jobs 的 shell 任务身份及结果确认宿主日志精确路径，兼容旧版固定 jobs/<job_id>.log 路径。确认的日志不占默认产物扫描额度，不因为空或继续增长而自动改变交付材料；没有按 .log 扩展名或整个 jobs 目录排除。
- 日志仍按现有方式写入、返回日志尾部与真实退出状态，并沿用会话清理。读取执行证据和已有阻塞处理保持原有链路。
- 明确交付路径覆盖默认时间及日志用途，包括旧文件、宿主日志、同会话已登记的受管产物。原有通用路径权限保持不变；受管产物只按同会话登记的精确物理文件读取。
- 纯会话 workspace 等于 tmp 时，不再从另一条工作区补扫路径重新纳入宿主日志。无法读取的明确交付路径披露边界，不伪称检查成功；日志来源查询失败本身不增加交付条件。
- 文件预览保留现有字符预算，完整文件内容参与现有材料指纹与变化核对；明确交付字段也纳入现有验收状态指纹。旧就绪回执重新评估，不改变真实失败、阶段阻塞及审查裁量规则。

## 本地验证

新增 7 项回归覆盖：

1. 旧宿主空日志不让单人/多人设置下的只读问答调用终审模型，自由会话补扫也不重新纳入。
2. 三十个宿主日志不挤掉扫描窗口中的坏报告，普通用户 .log 文件仍接受检查。
3. 检查点序列化/恢复保留逻辑任务身份和原任务起点，新任务继承历史但不冒认旧写入；明确再次交付旧成果仍纳入。
4. 明确交付的旧日志接受异常检查，旧报告在预览节选之外的内容变化仍影响指纹。
5. 实际写入线索补足时间扫描，跨会话路径不被读取。
6. 正式 evaluate_completion 路径将旧文件正文交给本地假模型，稳定材料复用、文件变化重新审查。
7. 同会话受管产物按 artifact_id 交付可检查，其他会话不能借用，通用目录权限不扩大。

相关定向回归 148 项通过：reviewer_gatekeeper 83、finalization 37、task_resume 8、work_history 12、review_control 8。最终新增 7 项再次通过，cargo check --offline --tests、cargo build --offline、git diff --check 通过；保留既有 reviewer_persona 未读赋值警告。使用临时数据库及隔离应用数据目录，不调用外部付费模型，不修改真实业务工程或历史记录。没有运行完整 Rust 测试套件，也没有重启桌面应用。
