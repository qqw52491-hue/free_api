## 当前界面状态：终审接入原有紧凑成员行

独立 AgentReviewProgress 大区域仍不挂载。终审复用 AgentWorkerProgress，插入实际 finish/prepare_finish 步骤下，简报与全量两种视图均接入，删除答案/产物后的独立列表。首次有效事件仅绑定唯一运行中的终态步骤，后续固定该锚点；归档后按同一 run ID、逻辑 step ID 和尝试序号保持原位。不按角色、描述或最近时间猜归属。缺少可靠关联时仅在最终回答之前的步骤区显示未关联进度，不伪造子任务。

运行中的成员默认展开：头部显示角色、真实阶段及观测耗时，下方显示请求/取证/本次片段计数，以及最高 66px（约三行）的局部动作滚动区。只保留最近 24 次宿主阶段/动作变化，心跳不制造新动作；自动跟随局部尾部，用户上翻后暂停，回底恢复。真实终态或父任务结束后自动收成一行结果与耗时，仍可手动展开；手动折叠在同一尝试内不会被心跳重开。模型、异常和完整计数说明在二级诊断详情内，不默认撑大界面。

方案审查、阶段审查、单人成员及写入/侦察等已接入执行流的子 Agent 统一复用同一紧凑组件；简报与全量均按原派发身份挂载，不在等待步骤重复放置旧协作大卡。运行/待派发默认展开，普通子任务显示已上报的最近步骤、当前动作与真实思考尾部（默认最多 4000 字符、66px 局部滚动）；没有思考或步骤也显示真实当前状态，不补造请求预算、完成百分比或吞吐。完整思考按需二次展开，原始内容不截断。完成/父任务结束原位收起，保留已有耗时；手动折叠不被后续片段重开，各成员局部滚动互不干扰，身份按钮仍打开原 inspect。终审使用独立 review 身份，不伪造 child ID、不打开不存在的子任务检查器；只展示宿主阶段和计数，不转发不存在的原始思考正文，也不把字符片段数伪装成 token 吞吐。停止后缺失终态显示未完成，调用失败与真实阻塞保持区分。位置计算只依赖身份/锚点签名，计数心跳不重建步骤分组。

速度补充：终审每次成功完成模型请求后，既有进度事件附带该请求序号、供应商回报的输出 token、首片段耗时与输出均速。均速为输出 token 除以首片段至请求结束的时间（须大于 50ms），不含前置等待与工具时间，不累计混合多轮，不使用传输层可能按字符估算的速率。新请求进行时明确这是最近已结束请求，不当成实时速度；无 usage、无片段或采样区间过短时速度为空，不以 0 冒充。普通子 Agent 的独立事件本轮未增加 token 指标，不能据终审速度推算它们。取证文案改为“已用 / 上限 次”，默认 8、封顶 30 的真实只读取证限制保持不变；模型请求次数、补正及重试另计，不是总进度。

仅增加终审观测字段和前端连接，不改触发、预算、人数策略或裁决协议，不停止/重派任务，不刷新或重启桌面应用。打包版本需更新前端后生效；内存投影仍不回填历史。下述旧大区域默认展开与复制行为仅是保留组件的历史实现记录，不代表当前主界面。

## 范围

复用现有终审进度事件，补充宿主确定的失败分类、超时重发数、格式补正数及流类别；调整多人终审对不可用成员的聚合策略。不修改模型提示词、有效成员裁决、预算、超时、重试策略或恢复规则。

- 分开显示：通过、阻塞不通过、请求超时、调用失败、输出格式无效、配置加载失败、明确停止、结束原因未确认、跳过。
- 非有效结论不展示成代码不合格。未知结束原因不根据文案或父任务状态猜为主动停止。
- 请求数为终审外层逻辑调用数；超时重发数不包含底层 HTTP/密钥重试。格式补正与取证步骤独立统计。
- 旧事件缺少新增计数字段时显示“未知”，而非伪造 0；原有事件字段语义保持不变。
- 任务收尾保留当前各成员最新尝试的观测卡；仅已知尝试的晚到事件可补齐诊断，下一次运行仍清空，不能重新激活已结束任务。
- 按用户反馈移除聊天区顶部固定大卡，放在左侧执行流。每位成员默认展开几行：角色名与阶段、实际当前动作、耗时、逻辑请求和取证统计；流接收时显示片段字符数，发生超时重发或格式补正时直接显示对应次数。最近异常也默认可见，不需要先点击详情。
- 多成员使用“联合终审”标题，各成员独立分组与状态标记；不伪造每位专家正在核验的具体议题，不把阶段动画或取证步数当完成百分比。只有模型信息、完整计数解释等补充诊断默认闭合，展开区限高滚动；复制仍由用户点击触发。
- 新增 stream_kind 宿主枚举：仅实际收到 Thinking 片段才显示“正在思考”，Content 显示“正在生成结论”，旧事件仍显示“接收中”。只转发类别和计数，不转发思考或响应正文；同类型后续片段不逐 token 广播，沿用心跳。
- 保留用户新修改的子 Agent 独立进度行；终审没有 child ID，不伪造子任务或猜测派发步骤，不写入其台账。状态首次出现时复用执行流已有跟随滚动逻辑，心跳不触发自动展开。
- 取证默认 8 次、配置封顶 30 次，以及主执行默认 300 步等既有预算均未修改。

## 审查触发与人数分离

- 修复多人开关绕过原有免审的回归：先判断是否需要模型审查，再确定单人或多人；不再以人数选择强制启动终审。
- 无新增写入、无本轮会话产物且无机械异常的只读问答，仍走既有直通；已有工作区改动不算本轮写入。triage 为 mechanical_only 且无机械异常时，仍只做上游既有机械核验，不调审查模型。
- 多人派发前和单人路径共用同一免审判断；免审不解析专家名单、不生成成员进度事件，也不发送多人派发日志，因此不会仅为一次免审问答创建联合终审区域。
- 产物零字节/魔数异常仍升级审查，不按“简单”“神经网络”等自然语言关键词、回答长度或模型自评增设免审规则。正式写入/产物审查、有效阻塞和其他交付门禁保留。
- 回归将原先“mechanical_only 也强制三人”的用例改为真实写入且需要产物质量审查的任务，继续验证三路并发；另覆盖单/多人免审零请求、无成员进度/派发日志及机械异常不能直通。本轮不新增或重排界面，不自动续跑真实会话。

## 部分成员不可用的收束规则

- 方案会审已支持部分成员失败后的有效裁决，本轮补回归，不改其状态归属协议。
- 终审等已派发成员全部返回有效结论或已知失败后再聚合；没有“一位先通过就取消其他人”。不可用成员排除，不算批准，也不单独令整轮失败。
- 至少一位有效通过且没有有效反对时，终审通过；只有一位有效结论时披露实际为单人审查。有效成员提出的阻塞仍拦截，评分只参考有效结论。
- 全部不可用仍为审查未完成，不伪造通过；明确停止也不因已有部分通过而交付。所有原始成员摘要保留，未更改超时、重试、备用和其他交付门禁。

## 脱敏复制

复制由用户点击触发；不自动上传。使用字段白名单，只导出固定诊断文案、成员序号、观测耗时和计数。

不包含自定义角色/模型名、会话/任务/审查标识、源码、文件路径、请求地址、密钥、提示词、原始响应、思考内容或任意异常原文。不是完整日志导出。

剪贴板失败时尝试本地复制降级；仍失败则显示可手动选择的脱敏摘要。切换尝试会清除旧复制提示和手动摘要；异步复制完成不会污染新一轮提示。

## 限制
