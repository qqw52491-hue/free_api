## 新流程

1. `ask_human` 等待真实用户回复；记录提问、原话、宿主生成的 reply_id 和本次被询问的操作范围，保存到 checkpoint。
2. 普通文字不直接产生许可，也不按“非空回复”放行。主模型在正常下一轮看到原话和动态状态，理解用户意图；无需额外调用一个审批模型。
3. 主模型可用顶层 `human_reply_decision` 随下一项操作提交判断，也可单独提交。只解释或不处理时可以不填，不新增每次回复必须表态的硬义务。
4. 宿主仅检查 reply_id、命令范围、布尔类型等事实，保存模型判决及原话。不包含肯定/否定词表，不按文案是否“像同意”改判。
5. 原有明确结构化批准/拒绝按钮直接消费对应布尔结果；无有效按钮标记的文字仍由主模型理解。取消或通道关闭不能伪造成一条真实用户授权来源。
6. 结果与 prepared_instruction 恢复时幂等对账，不重复生成许可。旧的纯文字 confirmed 数组只兼容读取，不再作为有效授权。

授权另外绑定原始命令（保留引号内空白）、真实 cwd、HEAD/index 和目标范围内现有脏文件内容。另一目录或相关内容变化不能沿用旧许可；无关路径变化不使同一许可失效。旧的自然语言方案审批、无法判定后默认放行及特赦关键词分支一并退出；原有按钮和审查待办来源核销方法复用。

## 正确回滚

任务开始是 B，Agent 修改后是 C：撤销本轮应回到 B。`git checkout --` 与默认 `git restore` 的来源是暂存区；它们不能代表任务开始状态。

主 Agent 首次进入有原有修改的任务时收到起点来源和逐文件对照；终审主材料及普通 Git diff 取证结果也附同一份来源事实。专用 git_diff 保持任务起点语义；普通命令不被偷偷改写。

对已核对属于本轮修改/计划范围的精确文件，明确指定：

```bash
git restore --source=<任务起点快照SHA> --worktree -- <精确文件路径>
```

该形态只恢复工作区，不修改暂存区。对任务前已有修改的文件，宿主额外核验快照内容哈希与起点记录一致；即使 base_head 因快照失败回退到 HEAD，也不能因此把旧提交误当作包含用户原有内容的快照。未登记目标仍走原保护，修改暂存区的形态不享受此工作区恢复通道。

整文件恢复会撤销该文件起点后的全部变化，不能自动区分后来第三方修改。应先对照、只选择本轮目标；遇到叠加修改应局部撤销或保留并披露。未跟踪文件只有哈希时不能承诺完整内容恢复。本轮不实现任意 Shell 的完整解析或通用三方合并。
