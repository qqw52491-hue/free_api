# MCP 参数发现与方案、交付审查移交修补

## 事故依据

只读核对本机运行 `1d4827d2-75d8-42ac-ab17-6dc9cc77deb5`：执行模型为
`gpt-5.6-terra`，15 条能力搜索记录，6 次 finish 被拦，最终由用户停止。
另一条 `bd3ab9bc-7bac-4d40-af8b-ba49e6fc8c7e` 使用 `gemini-3.8-flash-high`，
通过 Shell/Python 生成表格，修正旧新闻来源后完成。两条的验证命令、来源与执行路径不同，
不是足以判断模型整体能力高低的受控实验。

第一条运行的能力搜索多次只返回 `excel/write_range` 的简介和 next_tool_hint，
模型曾将 next_tool_hint 填进 command，触发缺少 query 的错误。原工具允许加载参数，
但需要模型另外理解顶层预加载协议。

第一轮方案回复包含 approved、revised_verification 与 final_only 发现；主 Agent 随后重交。
本地回归进一步确认：方案写入门把 final_only 也计入当前阻塞，不只是文案容易混淆。
第二轮审查以尚无实际表格和写后结果为由 rebuttal；这是模型裁量问题，不能机械忽略裁决。

实际产物为中文文件名，契约命令指向另一个英文文件名，并在会话 tmp 根内再引用相对 tmp/。
Agent 多次直接验证中文文件后，仍被要求证明最终文件可解析，随后创建兼容副本。
代码检查确认，多行 Shell 回执的证据索引仅取前两行，通常没有正文输出中的路径、行数和 PASS。
原始 output_id 仍可读，不能据此断言原文丢失，或认定摘要是模型误判的唯一原因。

## 修改

- MCP 宽泛搜索仍返回轻量目录，并增加可直接执行的 load_request；query 精确匹配完整工具 ID
  时返回该工具原始 input_schema 与完整描述，不执行该 MCP，不展开其他候选的参数。
- 错填 next_tool_hint 的错误说明字段位置及精确查询的合法形态；常驻工具说明与核心提示同步。
- 子侦察入口补上真实 dispatches 批量例子，明确异步任务不放入同步 parallel。
- 方案门和状态投影仅把非 final_only 发现计入当前阻塞；原始发现、待办及交付核销仍保留。
  旧检查点只有阻塞标量时保留原值，不猜测它属于哪一阶段。
- 方案回执在本批收齐、没有当前阻塞或修订/升级裁决且有正式方案时，突出本批审查已通过；
  不替代人工授权。发现展示保留 finality，执行前审查上下文明确当前对象是方案。
- Shell 索引保留命令开头/末尾与 stdout/stderr 首尾，每条预算为 600+700 字符加节选标记；
  15 条窗口、任务起点、原始 output_id 与原文读取方式不变。退出 0 不推导业务合格。
  终审规则指纹升版，避免直接复用旧投影下的裁决。
- 将现有路径纠错说明接入 finish/prepare_finish 实际使用的失败格式器。明确内嵌脚本路径修订的
  现有限制，不建议为错误文件名制造额外副本。不扩大冻结命令的可改范围，不跳过失败验证。

## 成本与边界

不新增模型调用、计数器、质量门禁或数据库字段。精确工具查询与 Shell 摘录会增加对应回执的
字符数；宽泛搜索和窗口数量保持原样。方案阶段处理依赖审查员已经声明的 finality，不从自然语言猜测。
明确 rebuttal、当前阶段阻塞、冻结验证失败及最终交付义务仍然有效。

内嵌 Python 等任意脚本中的文件路径仍不能安全地自动改写。本次没有把“像路径的字符串”当成
可任意修改的验收目标；该情形仍需通过现有方案/契约流程处理。未宣称彻底消除模型重复提交。

## 后续：经用户授权将过程手续降为建议

本节是后续减法，取代前文“不扩大冻结命令可改范围”的本轮旧边界。
用户明确要求保留有用的方案审查和终审，大幅减少过程限制与重复填报。

- 核验契约改为可选清单：复杂诊断、用户列了规格表，不再自动要求另建契约；
  普通审查建议沿用 finding/Todo，不再自动派生新义务。
- 验证方法可显式修订，切换到 evidence/human 会清除旧命令/脚本；
  方法更新改变契约指纹，旧执行回执不能冒充新方法的通过。省略字段仍保留原方法。
- closure_form 改为可选，允许核验方式待定、command 尚未给命令、human 保留 open。
  不再为了让状态闭合而要求把真人操作替换成机器断言或预先标 waived。
- finish/prepare_finish 共用评估链中，待办未更新、契约 open、引用对账未匹配，
  变为带原观察的终审参考；没有删除记录、伪造 done 或认定已经通过。
- 方案早期目标文件与实际产物未命中改为观察，不再独立打回并要求复审或制造同名副本。
  用户明确的交付路径仍由审查按用户目标核对，真实 scope/权限检查不变。
- 缺少手填写后验证不再自动推导并执行一条命令；推导结果只作建议，明确未执行。
  此分支沿用现有 Waived 收据表示宿主未追加自动验证，保留未测披露并移交终审，
  不生成 Verified 或宿主命令通过记录。显式契约命令仍执行且失败仍阻断；
  用户配置的额外检查仍沿原协议向终审提供实际结果。
- 终审收到完整 Todo/验证申报和契约；明确状态未同步不等于未完成，已有回执充分时直接采纳。
  更新审查规则与验收缓存版本，避免复用旧规则的就绪状态或拒绝。
- 核心与动态规则同步：工具选择、重读、自查次数、Skill 加载、固定交付标签及 self_report
  改为按需建议；子审查的全领域检查与固定 why 前缀也降为建议。
  预检失败不再顺带催填无关契约。用户明确要求、实际审查 blocking、权限、路径、并发保护保留。

## 再次本地排查：核心过程限制与执行入口一致性

用户要求继续仔细检查并落实能灵活的过程行为，保留核验清单作为参考，暂不扩大 tmp 改造。
本轮直接访问本机源码，没有通过 MCP 访问项目，没有改动真实 Agent 运行或产物。

### 本轮确认并修改的行为

1. 重复读取：原执行入口会在第三次同路径同窗口且采集内容相同时返回失败，
   与核心提示的“需要时可重读”冲突。现在只在首次达到观察阈值时提示，读取继续执行；
   提示明确未采集区间不在指纹结论内，不再要求“先修改文件才能重读”。
2. 历史同参失败：原入口按历史错误中的 ENOENT/required/权限等词拒绝再次派发，
   没有核对文件、环境或授权是否已改变。现在只提供历史步骤和原输出引用，
   当前调用继续接受真实参数、路径、权限与文件保护校验。
3. 人工提问：次数、相似文本与刚被门禁拦截的步骤间隔全部改为建议，
   不关闭人工输入、不强迫猜默认值、不宣称以前已经取得答案；
   自然语言授权的来源绑定和批准判决逻辑保持原样。
4. 批量子审查：原连续失败计数依据“成功启动数为零”，却按“格式解析失败”冻结后续三步。
   改为准确说明最近两批无成功启动，建议核对错误；恢复的旧冷却值清除并提示。
   当前参数、角色能力、写入权限和实际并发容量仍照常检查。
5. 长度代理：方案摘要不再至少 10 字，人工审批正文不再至少 30 字；仅检查非空。
   审批正文可以从 message 搬入 description，保留已有正文；标题不能冒充正文。
   内容是否充分交给审查员/用户判断，没有因此自动批准。
6. 核心过程指导：改前复现、唯一根因、完整方案先行、探索串行、失败两次换工具、
   必搜历史、偏好绝不询问、目标更新必换标题/分组、固定 thought/finding 间隔、
   编辑固定 2–3 行上下文与每阶段重复验证等改为按任务选择。
   已授权操作不要求重复确认；跨审查模式仍要取得完整有效结论，
   可以 wait_jobs 或正常自动回收，不强迫某一种回收动作。

### 保留的边界

用户已有改动与范围保护、精确编辑匹配、路径/权限、人工回复来源与版本对账。
JSON/工具 schema、并发容量、超时及模型调用资源预算仍是执行协议，未全部改为建议。

## 批量长回执按分支读取

针对多篇文章合并返回、第一篇很长而后续正文难以定位的问题，批量回执在完整 JSON 前增加
简短分支目录，显示原有分支 ID、工具、状态和正文开头。最多列出 20 个分支，正文预览有界，
完整结果仍保留。复用现有 output_id 与分支 ID，没有新增账本、登记或审查要求。

get_step_output 及 task_store 的读取/搜索动作支持可选 branch_id：先选对应分支，
再按该分支内部的字符位置分页或按行搜索。终审的回执读取/搜索同步支持此选项。
来源仍属于原始回执，跨会话限制与任务时间关系不变；读取不会再次执行抓取。
省略该参数维持整批读取，raw 可读所选节点的完整 JSON。缺失、重复或无效分支 ID
会明确报错，不会静默读到另一篇；旧记录保留完整结果 JSON 时也可选分支。
本轮支持按原始分支 ID 定位，没有加入按 URL 猜测匹配。

新增 4 项本地回归通过，覆盖长首篇后的定向读取、Unicode 分页、分支搜索、终审来源、
跨会话拒绝、旧格式、嵌套分支、失败/超时及歧义 ID；cargo check --tests 通过。
完整套件的后续收集被自动安全审查拒绝：其中有向 Bing 发请求的网络检索测试，
未将完整套件记为通过；后续只运行不访问外网的定向验证。
未重启桌面应用、未调用真实模型，模型实际是否选择该读取方式仍需运行观察。

## 多插件目录与能力发现

为接入更多服务保留轻量常驻目录。小插件的动作行增加服务原始简介节选；单插件超过
25 个动作时展示插件概要和浏览提示，不再把字母序前 25 项当作可见动作全集。
总工具数超过 80 时沿用插件级概要，不将所有完整参数常驻注入。

capability_search 复用原有入口，调整为：

- query 为插件名时返回该插件的真实动作目录，按 ID 排序，明确这不是相关性排名。
  支持 offset、total_matches、has_more、next_request，按实际返回条数续页，避免盲换关键词。
  单页最多 40 项，实际还受通用观测入口的 token 预算约束。
- 按动作关键词搜索时，最多 3 个候选在预算内直接附完整 input_schema；已附规格的项
  不再提供重复加载请求。超过自动展开预算的规格保持精确 load_request，不截断 schema。
  精确点名仍返回完整规格；特别大的精确结果沿用原来的原文保存和通用采样机制。
- 索引加入工具描述后续行的有界文本，并拆分 write_range 一类标识符，保留完整 ID 的
  优先级。未增加模型调用、嵌入服务或特定插件的动作白名单。
- 点名不存在的动作，或限定插件后的关键词没有匹配时，明确告知未命中并列出该插件
  的真实目录，不把其它动作伪装成同义替代。插件与内置工具同名时仍保留内置精确命中。
- 普通查询先组成完整、可展示的一页再返回，减少通用头尾采样切坏目录或参数的情况。
  每次查询的索引和规格共用同一份本地目录快照；浏览目录不展开所有 schema。

常驻说明、核心提示和每轮决策提示同步明确：已有具体名称和足够参数可直接调用；
查询已返回完整参数时无需再次查询。大插件说明书的节选也指向可翻页目录。
这些都是发现与展示调整，不新增执行步骤，不修改工具授权或实际执行参数。

本地回归覆盖超过 200 个工具的末尾动作发现、完整目录续页、参数直接返回、入口预算、
超大规格精确加载、未命中回退、命名冲突及 kind/namespace 过滤；仅使用本地假目录。
能力索引、MCP 目录、注册表、工具菜单与决策提示的 46 项定向回归全部通过；
