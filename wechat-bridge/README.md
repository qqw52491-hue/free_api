# 微信任务交互

在微信中直接发任务；任务执行中，普通消息会排队。

- `补充：颜色改成蓝色`：将要求加入当前任务，当前操作继续执行，后续步骤处理补充。尚未进入执行步骤、等待回答或核验交付时，会明确说明未接收。
- `回答：选择第一个`：回答当前提问。等待回答时也可直接回复；`回答：状态` 可以把“状态”当作答案正文。
- `文件`：手动重取上次任务生成的文件，最多 5 个，每个不超过 25MB；只取该次任务的产物。任务完成后也会自动回传这些文件。超限或发送未确认时会说明。
- 微信发来的文件在登记成功后交给任务读取；未绑定项目时使用临时工作区，不需要先选项目。登记失败时保留队列内容并说明失败。
- `状态`、`结果`、`帮助`、`项目`、`模型`、`文件`：等待回答期间仍作为指令处理。执行中或有排队任务时，查看项目列表可用，切换项目、新开会话和解绑需先结束任务并清空队列。
- `继续队列`：恢复暂停的排队任务。
- `跳过队首`：先在桌面端核对一次派发是否已经执行，再移除该条排队记录；不会停止已经启动的任务。
- `停止`：只停止当前任务，排队任务仍会继续。另发 `清空队列` 可以取消尚未派发的任务。

## 重启和断线

绑定、在途任务、等待回答、队列和上次完整结果一起原子保存到通道配置目录的 `wechat-bindings.json`，兼容已有绑定文件。桥重新登录后恢复已知运行的监听，保留进度里程碑，空闲时接续队列。

如果桌面应用的实时运行记录已清空，桥会按原 `run_id` 和 `session_id` 精确回查持久执行记录。存在终态时回传结果；没有可确认的终态时说明未知，保留并暂停队列，需核对后手动继续。这不等于自动恢复桌面 Agent 本身的执行。

任务派发前先保存“回执待确认”标记。请求发出后断线或进程退出，若没有收到运行编号，不自动重发；在 `状态` 中可看到保留的队首内容。核对桌面端后可跳过该记录，再继续其余队列。

完成结果先保存，再尝试发送。微信发送和本地保存无法组成原子事务，发送中进程退出时不能证明微信收没收到，因此不会自动重播；可发送 `结果` 手动重取完整正文。回答和补充也不会在网络回执未知时自动循环重发。

## 本地验证

在此目录运行 `npm test`，覆盖实际消息路由、并发派发、重启恢复和分段发送。测试不连接真实微信或付费模型。
