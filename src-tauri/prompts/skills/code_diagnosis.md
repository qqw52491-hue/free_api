# 故障排查参考

以下思路按问题选用，阅读范围、工具和调查顺序由当前任务决定。

## 定位与假设

异常信息和界面表现可以作为定位线索。必要时结合调用方、数据来源、状态更新、生命周期或样式，区分直接触发点与上游原因。修复后表现未变时，可以重新核对实际命中的组件、数据和运行环境。

检索片段不足以支持判断时，可继续读取相关上下文；阅读窗口和深度取决于尚未解决的问题。错误类型可用于检验假设，但框架包装或异常处理也可能改变最终呈现的错误。

## 证据与验证

静态代码、真实日志和运行时观测各有覆盖边界。可根据疑点选择能区分候选解释的验证方法，并考虑修改对调用方的影响。

报告如实区分观察事实、推断和未核验部分。静态阅读或编译通过不能冒充已复现、已消除用户症状；验证受限时说明缺失的证据即可，报告结构按任务需要组织。

任务复杂度、方案流程及验收要求沿用用户目标与当前执行模式。加载本 Skill 本身不新增调查清单、契约义务或交付门禁。
